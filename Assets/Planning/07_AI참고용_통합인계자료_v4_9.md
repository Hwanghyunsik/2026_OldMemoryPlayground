## v4.9 개정 요약 (v4.8 대체)

**SCR-019 개별 결과의 나열 방식을 SCR-020 간이 결과와 통일**했다. 데이터 항목은 그대로다.

| 구분 | 내용 | 위치 |
|---|---|---|
| **변경** | SCR-019 나열 — 5×2 고정 그리드 → **위·아래 2단 분리** (8-2 적용) | 6-9-3 |
| 유지 | 상단 요약 카드 3종 · 하단 버튼 3종 · 표시 금지 항목 | 6-9-2 · 6-9-4 · 6-9-5 |
| 정정 | SCR-018-1 도면 손상 5건 복구 (말풍선·글자 분리 등) | 도면 |

### 왜 바꾸는가

v4.8까지는 「완성 수와 다른 재료 수가 회차마다 달라 두 단의 카드 수가 매번 바뀐다」는 이유로
요리하기에만 2단 분리를 적용하지 않았다. **그런데 같은 요리하기의 간이 결과(SCR-020)는 2단 분리를 쓰고 있었다.**

한 게임의 두 결과 화면이 서로 다른 구조를 쓰면, 스토리 모드로 익힌 화면을 개별 모드에서 다시 익혀야 한다.

카드 수 가변 문제는 **각 단에 10칸 슬롯을 고정하고 남는 칸을 비워 두는 방식**으로 해소한다.
컨테이너는 고정이고 안의 카드만 바뀌므로 레이아웃이 흔들리지 않는다. SCR-020이 이미 쓰는 방식이다.

> 이로써 게임 3종의 결과 화면이 모두 **8-2 위·아래 2단 분리**로 통일된다.
> 개별 결과와 간이 결과의 차이는 **요약 카드 3종과 버튼 3종의 유무**뿐이다.

**판본 오염 정규화판이다. 규칙 변경은 없다.** v4.2까지 올리는 과정에서 뒤처진 상호 참조를 전량 일치시키고,

| 구분 | 내용 | 반영 위치 |

| **확정** | **참고시트는 화면 수에 넣지 않는다** — REF-U와 REF-A에 같은 기준을 적용 | 0-7 |

| 정정 | 21-2 감사 기준 — SVG **51장** · 화면 수 산식 | 21-2 |

### 관리자 화면 수가 15에서 13으로 바뀐 이유

**화면이 줄어든 것이 아니다.** 세는 방법을 통일한 것이다.

기존 산식 `ADM 9 + POP-A 4 + REF-A 2 = 15`는 REF-A가 2장이던 시절에 굳은 것이다. v4.1과 v4.2에서
REF-A가 4장 늘어 6장이 되었는데 산식은 2로 남아 있었다. 같은 문서 안에서 **REF-U 3장은 화면 수에서 빼고
REF-A만 넣는** 상태가 되어, 두 계열을 같은 기준으로 셀 수 없었다.

참고시트는 실제 화면이 아니다. 따라서 **양쪽 다 화면 수에서 뺀다.** 산출된 도면 장수는 그대로 51장이다.

### 0.5 기준의 근거

화면의 모든 값이 **소수 첫째 자리**로 표시된다. 반올림해서 0이 되는 구간이 정확히 0.5 미만이므로,
**「눈에 보이는 자리에서 차이가 없으면 변화로 보지 않는다」**는 뜻이 된다. 임의로 고른 값이 아니다.
지표별로 다른 임계값을 두지 않는다. 상수 하나로 네 지표를 모두 판정한다.

## v2.5 개정 요약 (v2.4 대체)

본 개정은 **와이어프레임 제작 과정에서 확정된 사항**을 반영한 것이다. 게임 규칙의 신규 확정은 없다.

### 이번 개정에서 확정한 사항

1. **시스템 타이틀 가제 확정** — 「신명놀이터」(가제). 태블릿 인지재활 제품 「두뇌놀이터」와 시리즈 관계.
2. **와이어프레임 산출 현황 신설**(15장) — 화면별 최신 버전과 상태를 문서에 고정.
3. **화면 유형별 공통 구조 확정**(2-4 신설) — 선택 화면 · 영상 화면 · 튜토리얼 화면 · 플레이 화면 · 간이 결과 화면.
4. **장보기 플레이 화면 표현 규칙 확정**(5-9 보강) — 바닥면 위 입체 발판, 점포 지붕 없음·축소 배치.
5. **간이 결과 수집물 표시 규칙 확정**(8-2) — 종류 단위 묶음 + 개수 배지, 위·아래 위치와 기울임으로 구분.
6. **인터랙티브 HTML 프로토타입 방식 확정**(16장 신설) — 판정값 검증 표준 절차.
7. **요리하기 세부 기획 필요 상태 명시**(6장·12장) — 와이어프레임 작업을 SCR-018까지 진행 후 중단.

### v2.4에서 이어지는 확정 사항

- 장보기 = 5발판 구조 (점포 4개 세로 1:1 정렬 / 10라운드 / 통과·도착 구분 / 자세 유지·유지 게이지 폐기)
- 튜토리얼 = 짧은 동영상 + 단계별 설명, 실습 단계 없음
- 개별 결과·간이 결과는 각각 독립 페이지 제작
- 전체 활동 시간은 일시정지 시간 제외
- 힌트 발동 후 성공도 정답 처리
- 문서에 예산 등 구체 금액을 기재하지 않는다

## v2.4 개정 요약 (v2.3.1 대체)

본 개정은 프로젝트 지식베이스에 있던 **별도 작업 문서를 본 문서로 통합**한 것이다.

### 통합한 자료

| 원본 자료 | 처리 |
|---|---|
| 「장보기 게임 5발판 시스템·UI 인계자료 v1.0」 + 와이어프레임·레이아웃 참고 이미지 | **최신 확정안으로 채택** → 5장 전문 통합. 구 5장(3분할 + 자세 유지)은 폐기 |
| 「SCR-006 / SCR-008 와이어프레임 작업 인계 자료」 | **구조 참고용으로만 유지.** 화면 번호·게임 명칭·스타일 표준은 채택하지 않음 (아래 0-4) |

### 이번 개정에서 확정한 사항

1. **장보기 = 5발판 구조**로 전면 재설계 확정 (5장 전체 교체).
   - 5발판 + 점포 4개 세로 1:1 정렬 / 10라운드 고정 / 목표 1~3개
   - 통과와 도착 구분 판정, **자세 유지·체중 싣기·유지 게이지 폐기**
2. 2-2 장보기 유지 게이지 조항 **폐기** 처리.
3. 튜토리얼 구성 = **짧은 동영상 + 단계별 설명**, 실습 단계 없음 (7장).
4. 와이어프레임 제작 기준과 공통 UI 표준을 **현재 작업 기준으로 통일** (0-4, 신설 2-3).
5. 11-3 장보기 개발 검증 항목을 5발판 구조 기준으로 교체.

### v2.3.1에서 이어지는 확정 사항

- SCR-023은 화면목록에 **정식 등재** · 구성 확정 — 가등재는 SCR-021뿐
- **힌트 발동 후 성공도 정답으로 처리**
- 개별 결과와 간이 결과는 **각각 독립된 개별 페이지로 제작**
- **전체 활동 시간은 일시정지 시간을 제외**하고 계산
- 문서에 예산 등 구체 금액을 기재하지 않는다

2. 스토리 모드 흐름에서 연결 연출이 3회 반복되는 것처럼 보이던 문구를 수정했다.
   - 연결 연출은 **수확하기 이후 1회, 장보기 이후 1회**, 총 2회다.
3. 공통 힌트 규칙의 표현을 `10초 미해결` 중심에서 **10초 동안 선택 행동이 발생하지 않은 상태** 중심으로 구체화했다.
4. 요리하기는 레시피 전체 완성이 아니라, **재료 선택 과정에서 10초 동안 아무 재료도 선택하지 못한 경우** 힌트가 표시되도록 정리했다.
5. 장보기와 요리하기는 잔치 스토리 적용 과정에서 교체된 게임이므로, 현재 확정된 핵심 골격과 아직 결정하지 않은 세부 규칙을 분리했다.
6. 개인 누적 성과 이력 화면(SCR-023)의 상태를 명시했다.
7. 이전 버전의 내용을 임의로 추가 확정하지 않고, 현재까지 합의된 내용과 미결정 사항만 구분해 수록했다.

### 상태 표기 5종

| 표기 | 의미 | 정하는 주체 |

> 이 항목은 개발팀 판단에 따른다.
> 구현이 어렵거나 공수가 과다하면 **기존 방식 또는 개발팀 추천 방식으로 수정 가능**하다.

### 작업 영역 구분

> **기획은 「무엇이 필요한가」와 「왜 필요한가」를 정한다. 「어떻게 만들 것인가」는 각 파트에 맡긴다.**

정합성 점검에서 절번호 중복과 낡은 수치 잔존이 확인되어 아래를 확정한다.

## 0-6. 밸런스 문서 방침 (확정)

> **플레이 밸런스에 해당하는 수치는 본 문서에서 확정하지 않는다.**
> **화면설계서 완성 후 별도의 밸런스 문서에서 일괄 확정한다.**

| 항목 | 기준 |
|---|---|
| 대상 | 라운드별 구성 비율 · 임계 거리 · 유지 시간 · 반복 주기 등 **플레이 체감을 좌우하는 수치** |
| 시점 | **화면설계서 완성 이후** 착수한다 |
| 그 전까지 | 도면·문서의 수치는 **예시 또는 기준안**이며, 확정으로 읽지 않는다 |
| 표기 | 해당 항목은 **「밸런스 문서」**로 표기한다. 「결정 예정」을 쓰지 않는다 |

화면 구조가 닫히기 전에 수치를 확정하면, 구조가 바뀔 때마다 수치를 다시 잡아야 한다.
구조를 먼저 닫고 수치를 나중에 채우는 순서다.

> **「밸런스 문서」로 표기된 항목은 미결정 목록(12-2)에 올리지 않는다.** 별도 문서에서 관리한다.

## 0-4. 참고 자료의 지위

프로젝트 지식베이스에는 다른 작업 흐름에서 만들어진 자료가 함께 있다. 각 자료의 지위는 다음과 같다.

| 자료 | 지위 | 사용 범위 |
|---|---|---|
| 장보기 5발판 인계자료 v1.0 + 와이어프레임 + 레이아웃 이미지 | **최신 확정안** | 본 문서 5장에 통합 완료. 점포·발판 세로 1:1 정렬은 원본 이미지를 그대로 참고한다 |
| SCR-006 / SCR-008 와이어프레임 작업 인계 자료 | **구조 참고용** | 오브젝트 입체 표현·배치 구조 등 아이디어 참고만 허용 |

### SCR-006/008 자료에서 채택하지 않는 것 (중요)

해당 자료는 구 화면 번호 체계로 작성되어 있어 그대로 읽으면 혼선이 발생한다.

- 화면 번호: 구 자료의 SCR-006·008·010은 **현행 v6.3과 무관하다.** 현행 SCR-006은 오프닝 스토리 영상, SCR-008은 수확하기 플레이다.
- 게임 명칭: 울타리 열매 따기 / 정답 발판 찾기 / 심부름 물건 기억하기는 모두 **구 명칭으로 폐기**되었다. 현행은 수확하기 · 장보기 · 요리하기다.
- 스타일 표준: 해당 자료의 그레이스케일 마스터 스타일·클래스 정의·좌표표는 채택하지 않는다. 와이어프레임 제작 기준은 2-3을 따른다.

## 0-7. 화면 수를 세는 기준 (확정 · v4.3 신설)

**참고시트는 화면 수에 포함하지 않는다.** REF-U 계열과 REF-A 계열에 같은 기준을 적용한다.

| 구분 | 수 | 산식 |
|---|---|---|
| 사용자 화면 | **29** | SCR 27 + POP 2 |
| 관리자 화면 | **13** | ADM 9 + POP-A 4 |
| **화면 합계** | **42** | |
| 참고시트 | 9 | REF-U 3 + REF-A 6 |
| **산출 도면 합계** | **51장** | 사용자 32 + 관리자 19 |

참고시트는 여러 화면에 걸친 공통 규칙을 한 장에 모은 설명 자료이며 사용자나 담당자가 도달하는
화면이 아니다. 화면 수와 도면 장수를 나누어 적으면 두 값이 서로 어긋날 일이 없다.

# 1. 전체 콘텐츠 방향

## 1-0. 시스템 명칭 (가제)

| 항목 | 내용 |
|---|---|
| 시스템 타이틀 | **신명놀이터** (가제 — 최종 확정 아님) |
| 시리즈 관계 | 태블릿 인지재활 제품 「두뇌놀이터」와 같은 제품군 |
| 표기 원칙 | 확정 전까지 사용자 화면·문서에 **「가제」 표기를 병기**한다 |


## 1-1. 잔치 준비 스토리

전체 콘텐츠는 다음 흐름으로 진행한다.

```text
수확하기
→ 장보기
→ 요리하기
→ 최종 잔치상 완성
```

게임명에는 `잔치`, `시장`, `음식`을 붙이지 않는다.  
잔치와의 관계는 스토리 설명과 영상에서 전달한다.

| 게임 | 스토리 역할 |
|---|---|
| 수확하기 | 잔치에 사용할 작물과 채소를 수확한다. |
| 장보기 | 수확만으로 부족한 재료를 시장에서 준비한다. |
| 요리하기 | 준비된 재료를 기억하고 골라 잔치 음식을 만든다. |

## 1-2. 3종 게임의 신체·조작 분담

| 게임 | 담당 신체·조작 | 성격 | 현재 기획 상태 |
|---|---|---|---|
| ① 수확하기 | 팔의 동적 동작, 링 없음 | 동작 게임 | 세부 규칙 상당 부분 확정 |
| ② 장보기 | 하체·몸 중심 좌우 이동 (5발판 이동) | 이동 게임 | 5발판 구조 확정, 판정 기준값 세부 기획 필요 |
| ③ 요리하기 | 손 위치 유지 선택(dwell), 링 게이지 | 기억·선택 게임 | 핵심 콘셉트 확정, 선택·완성 규칙 세부 기획 필요 |

### 공통 조작 문법

> 게이지 링이 보이면 일정 시간 기다려 선택하고, 링이 없으면 해당 동작을 바로 수행한다.

## 1-3. 스토리 모드 정확한 흐름

```text
SCR-001 대기
→ SCR-002 사용자 감지·보정
→ SCR-003 사용자 선택
→ SCR-004 모드 선택
→ SCR-006 오프닝 스토리 영상

→ SCR-007 수확하기 튜토리얼
→ SCR-008 수확하기 플레이
→ SCR-010 수확하기 간이 결과
→ SCR-011 연결 연출 1

→ SCR-012 장보기 튜토리얼
→ SCR-013 장보기 플레이
→ SCR-015 장보기 간이 결과
→ SCR-016 연결 연출 2

→ SCR-017 요리하기 튜토리얼
→ SCR-018 요리하기 플레이
→ SCR-020 요리하기 간이 결과

→ SCR-021 엔딩 스토리 영상(가등재)
→ SCR-022 최종 잔치상 결과
```

### 중요

- 연결 연출은 총 **2개**다.
- 요리하기 간이 결과 이후에는 별도의 세 번째 연결 연출이 없다.
- SCR-021 엔딩 영상과 SCR-022 최종 잔치상 결과는 **별도 화면으로 유지**한다 (화면목록 v6.14 확정).
- 스토리 모드 종료 후 동선은 9-4에 확정되어 있다.

## 1-3-1. 모드 표시 명칭 (확정)

| 내부 명칭 | 사용자 화면 표시 명칭 |
|---|---|
| 스토리 모드 | **스토리 게임** |
| 개별 모드 | **개별 게임** |

- 사용자 화면(SCR-004 모드 선택)에는 위 표시 명칭을 사용한다.
- 문서와 개발 코드에서는 스토리 모드·개별 모드 표기를 계속 사용한다.
- 가칭 표기는 삭제한다.

## 1-4. 개별 모드 흐름

```text
SCR-001 → SCR-002 → SCR-003 → SCR-004
→ SCR-005 게임 선택 로비
→ 선택한 게임의 튜토리얼
→ 플레이
→ 개별 결과
→ 로비 복귀 또는 후속 선택
```

개별 결과 화면은 다음과 대응한다.

| 게임 | 튜토리얼 | 플레이 | 개별 결과 |
|---|---|---|---|
| 수확하기 | SCR-007 | SCR-008 | SCR-009 |
| 장보기 | SCR-012 | SCR-013 | SCR-014 |
| 요리하기 | SCR-017 | SCR-018 | SCR-019 |

장보기와 요리하기의 세부 규칙이 확정되기 전까지 SCR-014와 SCR-019의 상세 데이터 구성은 확정하지 않는다.

## 1-5. 스토리 모드 기본 원칙

- 각 게임 전에 튜토리얼을 표시한다.
- 각 게임 후에는 수치·점수·버튼이 없는 간이 결과 화면을 표시한다.
- 세 게임의 수행 내용은 마지막 잔치상에 종합 반영하는 방향을 유지한다.
- 점수, 등급, 성공·실패를 사용자에게 직접 표시하지 않는다.
- 모든 결과에서 음식과 잔치는 정상적으로 완성된다.
- 낮은 결과도 실패하거나 빈약한 잔치처럼 표현하지 않는다.

## 1-6. KPI와 사용자 수행 데이터 구분

| 구분 | 내용 |
|---|---|
| 사업계획서 성능지표 | 인터랙션 성공률 90% 이상, 반응속도 200ms 이하, 위치·동작 판정 오차율 5% 이하 |
| 의미 | 시스템의 인식·처리 성능 |
| 평가 | 공인시험기관의 사전 정의 시험 시나리오 기준 |
| 사용자 수행 데이터 | 정확 선택, 반응 시간, 유지 시간, 흔들림, 힌트 사용 등 |
| 표시 원칙 | 비노출은 미측정을 의미하지 않는다. 모든 모드에서 내부 측정·집계 가능 |

사업계획서 KPI를 사용자 정답률이나 게임 성공률로 해석하지 않는다.

## 1-7. 라운드 수 (확정)

**3종 게임 모두 10라운드로 고정한다.**

| 게임 | 1라운드의 단위 |
|---|---|
| ① 수확하기 | 목표 작물 1개 수확 |
| ② 장보기 | 목표 재료 1~3개 구매 후 중앙 복귀 |
| ③ 요리하기 | 음식 1개 완성 |

- 진행 레일은 전 게임 공통으로 **1~10**을 표시한다.
- 사용자 테스트 결과에 따라 조정할 수 있으나, 현 단계의 기준값은 10이다.
- 라운드 수를 게임별로 다르게 두지 않는다.

## 1-8. 사용자 아바타와 카드 색 (확정)

### 아바타

| 항목 | 내용 |
|---|---|
| 종류 | **8종 고정** |
| 계열 | **동물 · 과일 · 자연** 계열로 구성한다 |
| 선택 | 사용자가 8종 중 하나를 선택한다 |
| 사진 | 실제 얼굴 사진은 사용하지 않는다 |
| 표시 | 사용자 선택 화면, 모드 선택 헤더, 개인 기록 헤더에 동일 아바타를 사용한다 |

계열을 이렇게 정한 이유는 고령 사용자가 **이름 없이도 자기 것을 즉시 알아볼 수 있는 소재**이기 때문이다. 추상 도형이나 기호는 사용하지 않는다.

### 카드 배경색

| 항목 | 내용 |
|---|---|
| 배정 | **랜덤 배정** |
| 목적 | 카드 구분을 돕는 장식 요소다 |
| 제한 | 색으로 사용자 정보를 구분하지 않는다. 이름과 아바타가 식별 수단이다 |

### 구체 소재 — 디자인 판단 (확정)

**기획은 「8종 고정」과 「동물 · 과일 · 자연 계열」까지만 정한다.**
어떤 동물·과일·자연물을 쓸지는 **디자인 파트의 판단**에 따른다.

| 기획이 요구하는 것 |
|---|
| 8종이 서로 확실히 구분될 것 |
| 이름을 읽지 못해도 자기 것을 알아볼 수 있는 소재일 것 |
| 추상 도형·기호를 쓰지 않을 것 |
| 실제 얼굴 사진을 쓰지 않을 것 |

와이어프레임과 화면설계서에는 **X-Box 플레이스홀더 8칸**으로 표기하며, 소재가 확정되면 도안만 교체한다.

### 결정 예정

- 아바타 선택 UI의 위치 (등록 절차 내 / 별도 화면)
- 카드 배경색 랜덤 배정 시점 (등록 시 고정 / 화면 진입 시마다)

## 1-8-1. 이름 표기와 동명이인 (확정 · v4.6 신설)

| 항목 | 규칙 |
|---|---|
| **비회원 헤더 표기** | **「손님」** — 아바타 자리에는 등록 사용자와 구분되는 공용 표시를 둔다 |
| **동명이인** | **허용한다.** 같은 이름을 여러 명 등록할 수 있다 |
| 식별 수단 | 이름 + 아바타 + 카드 배경색 **조합** (1-8) |
| 이름 최대 글자 수 | **개발 판단** — 입력 필드 사양이다 (12-2 C11) |

**「손님」을 고른 이유** — 헤더를 비우면 등록 사용자 화면과 구조가 달라져 담당자가 오작동으로 오해한다.
「비회원」·「게스트」는 시설 어르신에게 낯선 말이다. 「손님」은 자리를 채우면서 뜻이 바로 통한다.

비회원은 기록을 저장하지 않으므로 「내 기록 보기」 버튼을 표시하지 않는다(8-5). 이 규칙은 그대로다.

## 1-9. 난이도 개념 (확정 · v3.3 재정의)

난이도는 **두 가지로 나누어 다룬다.** 하나는 폐기했고, 하나는 유지한다.

| 구분 | 처리 |
|---|---|
| **사전 난이도 선택** | **폐기** |
| **플레이 중 단계적 상승** | **확정 · 사용한다** |

### 사전 난이도 선택 — 폐기 (유지)

- 난이도 선택 화면, 난이도 설정 항목, 난이도별 분기를 두지 않는다.
- 사용자에게 난이도를 고르게 하지 않으며, 운영자도 난이도를 지정하지 않는다.
- 모든 사용자가 **동일한 조건**으로 시작한다.

| 폐기 항목 | 기존 위치 |
|---|---|
| 난이도 선택 시점 결정(로비 / 튜토리얼 / 운영자 지정) | 결정 예정 목록 |
| 튜토리얼 화면의 난이도 선택 영역 | SCR-007 · 012 · 017 |
| 설정 팝업의 기본 난이도 항목 | (구 POP-003 · 폐기) |

### 플레이 중 단계적 상승 — 확정

> **라운드가 진행되면서 과제의 폭이 자연스럽게 넓어진다.**

세 게임이 같은 문법을 따른다.

| 게임 | 점증 요소 | 구간 |
|---|---|---|
| ① 수확하기 | 선택지 수 | **3개(R1~R3) → 4개(R4~R7) → 5개(R8~R10)** |
| ② 장보기 | **발판 수** | **3개(R1~R4) → 5개(R5~R10)** |
| ② 장보기 | 목표 재료 수 | 1~2개(R1~R4) → 2~3개(R5~R10) |
| ③ 요리하기 | 재료 수 | 1개(R1~R2) → 2개(R3~R5) → 3개(R6~R10) |

### 표현 원칙

- 사용자에게 **「어려워집니다」라고 알리지 않는다.** 단계 안내, 레벨 표시, 축하·경고 문구를 두지 않는다.
- 확장은 **조용히** 일어난다. 해당 라운드가 시작될 때 자연스럽게 늘어난 상태로 제시한다.
- 사용자 화면에 「난이도」라는 말을 쓰지 않는다.
- 이것은 **어려워지는 것이 아니라 몸과 손이 풀린 뒤 범위를 넓히는 것**이다. 특히 장보기는 신체 부하 게임이므로 초반 이동 범위를 좁게 두는 것이 안전 설계이기도 하다.

### 후속 정리 — **완료**

1-9 최초 신설 당시 「단일 값으로 확정 필요」로 남겼던 항목은 전부 위 점증 규칙으로 확정되었다.

# 2. 공통 입력 및 UI 컴포넌트

## 2-1. 손 커서와 원형 채움 게이지

| 항목 | 현재 기준 |
|---|---|
| 손 커서 | 손 위치 추종 아이콘 |
| 게이지 링 | 선택 영역 진입 시 표시 |
| 게임 오브젝트 선택 유지 | 2초 |
| UI 버튼 선택 유지 | 3초 |
| 선택 영역 이탈 | 즉시 리셋 |
| 완료 피드백 | 효과음 + 대상 강조 |

### 설계 원칙

- 판정 영역은 시각적 오브젝트보다 넓게 설정한다.
- 인접 선택지의 판정 영역이 겹치지 않게 한다.
- 게이지는 색상만이 아니라 두께·채움 각도 변화도 함께 사용한다.
- 약 3m 시청 거리에서 식별 가능한 크기로 설계한다.
- UI 버튼은 게임 오브젝트와 손 이동 경로가 겹치지 않게 배치한다.
- 튜토리얼 내 실습(1회 연습)은 두지 않는다. (확정 — 구 「튜토리얼 1회 실습」 원칙 폐기)

### 게임별 조작은 같지 않다 (확정 · v4.4 신설)

> **손 커서와 게이지 링을 쓰는 것은 UI 버튼과 요리하기 재료뿐이다.**

수확하기와 장보기는 dwell로 선택하지 않는다. 세 게임이 같은 입력 문법을 쓴다고 서술하면
개발이 같은 판정 모듈로 구현하게 되어 두 게임의 신체 활동 목적이 사라진다.

| 대상 | 조작 | 게이지 링 |
|---|---|---|
| UI 버튼 | 3초 dwell | 표시 |
| ③ 요리하기 재료 | 1~2초 dwell (기준안) | 표시 |
| ① 수확하기 작물 | 영역 진입 후 **손을 아래로 이동** (4-4) | **없음** |
| ② 장보기 발판 | 몸 중심 **위치 이동 후 정지** (5-8) | **없음** |

한 문장으로 줄이면 이렇다.

> **게이지 링이 보이면 머무르고, 보이지 않으면 몸을 움직인다.**

## 2-2. 장보기 유지 게이지 (폐기)

장보기는 5발판 구조로 전면 재설계되면서 **자세 유지 게이지를 사용하지 않는다.** (5-8 참조)
손 커서와 게이지 링은 UI 버튼·오브젝트 선택 화면에서만 사용한다.

## 2-3. 와이어프레임 제작 및 공통 UI 표준 (확정)

와이어프레임은 **현재 작업 기준 하나로 통일한다.** 다른 흐름에서 만들어진 스타일 체계는 채택하지 않는다.

### 제작 기준

| 항목 | 기준 |
|---|---|
| 캔버스 | 1920×1080, `viewBox="0 0 1920 1080"` |
| 스타일 정의 | `<defs><style>` CSS 클래스 기반 (인라인 속성 금지) |
| 기준 문서 | 스타일 가이드 v2.7 |
| 산출 형식 | 피그마 임포트용 SVG, 레이어 그룹 분리 |
| 레이어 구성 | `layer-background` / `layer-main` / `layer-annotations` |
| 도안 확정 전 콘텐츠 | X-Box 플레이스홀더(점선 사각형 + 대각선) |
| **게임 오브젝트·배경 일러스트** | **반드시 X-Box 플레이스홀더로 표현한다.** 작물·재료·음식·점포·상품 등 아트 대상을 SVG 도형으로 흉내 내어 그리지 않는다 |
| X-Box 라벨 | 박스 중앙에 흰 라벨 칩을 얹고 무엇이 들어갈 자리인지 한글로 표기한다 |
| 설계 주석 | 붉은 점선 배지 + 번호 원. **화면 설계서 전용이며 실제 화면에 표시되지 않음**을 문서 하단에 명기 |
| **주석과 UI의 관계** | **UI 배치는 주석 때문에 이동시키지 않는다.** UI를 화면 중앙 기준으로 먼저 확정하고, 주석은 그 위에 오버레이로 얹는다. 주석 자리를 만들려고 본문을 한쪽으로 몰지 않는다 |
| 주석 배치 | UI 요소의 바로 위·아래 여백을 우선 사용하고, 연결선은 짧은 가로 또는 세로 직선으로 한다 |
| 미결정 영역 | 붉은 점선 자리표시로 남기고 임의 확정하지 않는다 |

### 텍스트 규격

- 사용자 화면의 모든 텍스트는 **20px 미만 금지**, 본문 26px 이상을 기준으로 한다. (3-4 원칙)
- 설계 주석 텍스트는 문서 전용이므로 위 규격 적용 대상이 아니다.

### 화면 공통 UI 구조 (선택·안내 화면)

| 영역 | 구성 |
|---|---|
| 상단 헤더 | 안내 문구 패널(좌측 포인트 바) + 현재 사용자 표시 |
| 본문 | 카드 그리드 또는 좌우 2분할 |
| 하단 바 | 좌측 복귀 버튼 · 중앙 안내 또는 주 CTA · 우측 보조 버튼 |
| 선택 조작 | 손 커서 + 게이지 링. 진행 상태를 와이어프레임에 예시로 표시한다 |
| 목록 이동 | 그리드 바깥 좌우 세로 버튼 + 현재 쪽 표시. 그리드 안에 이동 카드를 넣지 않는다 |

### 플레이 화면 공통 HUD (확정)

전 게임 공통으로 아래 배치를 사용한다. 게임별 고유 요소는 중앙 플레이 영역에만 둔다.

| 영역 | 구성 |
|---|---|
| 하단 중앙 | 일시정지 버튼 |
| 상단 중앙 | 현재 목표 제시 패널 |
| 상단 우측 | 경과 시간 표시 (시간 제한 아님 · 유지 여부 재확인 가능) |
| 우측 세로 | 라운드 진행 레일, 현재 라운드 강조 |
| 중앙 | 게임별 플레이 영역 |

- 진행 표시를 **두 곳에 중복 배치하지 않는다.**
- 플레이 화면에는 긴 설명 텍스트 바를 두지 않는다.
- 플레이 화면에 설명용 인물·관절 포즈·외부 주석을 넣지 않는다.

### 결정 예정

없다. 경과 시간 표시는 유지로 확정(5-9)되었고, 일시정지 팝업 구성은 8-7에서 확정되었다.

## 2-4. 상호작용 안전 영역 (확정)

본 시스템은 **대형 TV 화면 + 비전 카메라** 환경이다. 사용자는 화면에서 약 3m 떨어져 서 있으며, 손을 뻗어 화면 위 대상을 선택한다.

화면을 넓게 쓰면 사용자가 **팔을 크게 뻗거나 몸을 옆으로 옮겨야** 선택할 수 있다. 이는 고령 사용자에게 부담이고 낙상 위험도 있다. 따라서 모든 인터랙션 요소의 배치 범위를 아래와 같이 제한한다.

### 영역 정의 (1920×1080 기준)

| 구분 | 범위 | 배치 대상 |
|---|---|---|
| **핵심 영역** | x 420 ~ 1500 / y 240 ~ 980 | **모든 인터랙션 요소**(선택 대상·버튼) |
| 허용 영역 | x 300 ~ 1620 / y 200 ~ 1040 | 부차적 조작만. 가급적 사용하지 않는다 |
| **금지 영역** | 위 범위 바깥, 특히 화면 상단과 좌우 끝 | 인터랙션 요소를 두지 않는다 |

### 방향별 기준이 다른 이유

본 시스템은 사용자가 화면을 직접 만지는 방식이 아니라, **3m 밖에서 손 위치를 화면 좌표로 매핑**하는 방식이다. 따라서 방향마다 신체 부담이 다르다.

| 화면 위치 | 실제 동작 | 부담 |
|---|---|---|
| 위쪽 | 손을 어깨 위로 올린다 | **높음** — 고령자에게 부담이 크다 |
| 좌우 끝 | 팔을 옆으로 뻗거나 몸을 옮긴다 | **높음** — 낙상 위험도 있다 |
| 아래쪽 | 손을 아래로 내린다 | 낮음 — 자연스러운 자세다 |

그러므로 **가로 범위와 상단 기준은 엄격하게 지키고, 하단은 상대적으로 완화**한다.

- 가로 x 420~1500은 완화하지 않는다.
- 상단 y 200 미만에는 인터랙션 요소를 두지 않는다.
- 하단은 y 1040까지 허용한다.

### 비인터랙션 요소는 예외

목표 제시 패널, 경과 시간, 진행 레일, 결과 나열, 배경 등 **선택 대상이 아닌 표시 요소**는 안전 영역 밖에 배치할 수 있다. 사용자가 손을 뻗을 필요가 없기 때문이다.

### 게임 설계상의 예외

**장보기(SCR-013)의 발판과 점포**는 좌우 이동 자체가 게임의 목적이므로 본 규정의 적용 대상이 아니다. 다만 이동 범위의 안전 한계는 5-11에서 별도로 정한다.

### 안전 영역 예외 (확정 · v2.7 신설)

안전 영역은 **게임 중 반복해서 손을 뻗는 요소**를 제한하기 위한 규정이다.
아래 두 경우는 그 취지에 해당하지 않으므로 예외를 적용한다.

| 예외 대상 | 배치 | 사유 |
|---|---|---|
| 영상 화면 건너뛰기 | 영상 영역 밖 **우측 상단** (x1472 y26 400×112) | 안쪽에 두면 영상을 가린다. 게임 조작이 아니며 사용 빈도가 낮다 |
| 장보기 일시정지 | **상단 좌측** (x48 y34 220×116) | 하단 전체가 발판이며 손 조작이 없는 게임이다 |

예외는 위 두 건에 한정한다. 다른 요소는 안전 영역 규정을 그대로 따른다.

### 일시정지 버튼 위치 (확정 · v2.7 개정)

| 항목 | 규칙 |
|---|---|
| 기본 위치 | **화면 하단 중앙 영역** · 220×100 기준 |
| 적용 | 수확하기(SCR-008) · 요리하기(SCR-018) |
| **예외** | **장보기(SCR-013)는 상단 좌측** (220×116) |

**장보기 예외 사유** — 하단 전체가 발판이라 하단 중앙에 두면 발판에 가려진다. 좌우로 옮길 자리도 없다.
더 중요한 것은 이 게임이 **손으로 화면을 누르는 조작이 없다**는 점이다. 발판 위에 선 채로
화면 아래쪽을 향해 손을 뻗으면 몸을 숙이게 되는데, 균형·이동 게임에서 가장 피해야 할 동작이다.
또한 하단 중앙은 중앙 발판 바로 아래라 "여기로 이동하라"는 표시로 오해할 여지도 있다.

### 영상 화면의 건너뛰기 (확정 · v2.7 개정)

건너뛰기 버튼은 **영상 영역 밖 우측 상단**에 배치한다. 영상 위에 겹치지 않게 하는 것이 우선이다.

## 3-1. TTS 전역 규칙

| 구간 | TTS |
|---|---|
| 게임 플레이 중 판정 반응 | 사용하지 않음 |
| 게임 플레이 중 힌트 | 사용하지 않음 |
| 요리하기 레시피 제시 | 사용하지 않음 |
| 튜토리얼 | 사용 가능 |

| 화면 전환 안내 | 사용 가능 |
| 일시정지 화면 | 사용 가능 |

플레이 중에는 효과음과 시각 연출로만 결과를 전달한다.

## 3-2. 10초 무선택 힌트 원칙

힌트는 사용자가 일정 시간 동안 다음 선택 행동을 하지 못했을 때 제공하는 보조 장치다.

### 공통 기준

- 기본 기준 시간은 **10초**다.
- 힌트는 정답 또는 다음에 찾아야 할 대상을 시각적으로 강조한다.
- TTS는 사용하지 않는다.
- 부드러운 효과음은 사용할 수 있다.
- 다른 선택지를 잠그거나 사용자의 선택을 강제하지 않는다.
- **힌트 발동 후 성공한 선택도 정답으로 처리한다.** (확정)
- 힌트 사용 여부는 내부 데이터로만 기록한다.
- 결과 화면에서는 힌트 사용을 구분 표기하지 않으며, 감점이나 실패로 표시하지 않는다.
- 반복 주기와 최대 반복 횟수는 게임별 세부 기획에서 확정한다.

### 게임별 적용 정의

#### 수확하기

- 한 라운드에서 목표 작물이 제시된 뒤 10초 동안 어떤 작물도 수확하지 못하면 힌트를 표시한다.
- 힌트는 목표 넝쿨의 시작 강조 연출을 다시 보여주는 방식으로 검토한다.
- 다른 작물을 수확하면 해당 라운드는 종료되므로 별도의 타이머 리셋 규칙이 필요하지 않다.

#### 장보기

- 한 라운드에서 목표 재료가 제시된 뒤 10초 동안 방향 선택이 완료되지 않으면 정답 방향을 시각적으로 강조한다.
- 방향 선택 완료의 정확한 판정 기준은 장보기 세부 규칙 확정 과정에서 정한다.
- 이동 중 움직임만으로 타이머를 초기화할지 여부는 아직 결정하지 않는다.

#### 요리하기

- 재료 선택 화면이 표시된 뒤 10초 동안 아무 재료도 선택하지 못하면 힌트를 표시한다.
- 재료 하나가 선택되면 해당 무선택 구간은 종료된다.
- 다음 재료 선택을 기다리는 시점부터 다시 10초를 측정한다.
- 레시피 완성 전 어느 단계에서든 10초 동안 추가 재료 선택이 없으면 힌트가 다시 발동할 수 있다.
- 정답 재료뿐 아니라 다른 재료를 선택한 경우의 타이머 처리도 `선택 행동 발생`으로 보는 방향을 현재 기준으로 삼되, 최종 선택 규칙과 함께 재검토한다.
- 힌트는 아직 선택되지 않은 레시피 재료 중 하나를 시각적으로 강조하는 방향이다.
- 어떤 재료를 우선 강조할지는 요리하기 세부 규칙에서 확정한다.

## 3-3. 다른 선택 처리 원칙

> 사용자의 행동을 강하게 부정하거나 게임 진행을 막지 않는다.

다만 게임별 세부 적용 상태가 다르다.

| 게임 | 적용 상태 |
|---|---|
| 수확하기 | 다른 선택도 라운드 진행 및 결과 기록에 반영하는 방식 확정 |
| 장보기 | 다른 점포에서 멈추면 그 재료를 그대로 구매한다 · 「다르게 산 재료」으로 기록 (5-11 확정) |
| 요리하기 | 레시피 외 재료도 슬롯에 담기고 슬롯 충족 시 일괄 판정한다 · 순서는 무관 (6-2 확정) |

세 게임 모두 **다른 선택을 그대로 수용하고 결과에 정직하게 남기는** 구조로 통일되었다.

### 사용자 대면 용어

- `오답`, `틀림`, `실패`보다 `다른 선택`을 우선 사용한다.
- 빨간 X, 큰 경고음, 감점 연출을 지양한다.
- 필요한 경우 정답과 다른 선택의 효과음을 구분한다.

## 3-4. 최소 텍스트 원칙

- 사용자 화면에 작은 텍스트를 사용하지 않는다.
- 1920×1080 기준 본문 26px 이상을 가안으로 한다.
- 어떤 보조 정보도 20px 미만으로 설계하지 않는다.
- 최종 수치는 실제 설치 거리와 고령 사용자 테스트 후 확정한다.
- 정보는 문장보다 그림·위치·크기를 우선 사용해 전달한다.

## 3-5. 사용자 화면과 관리자 화면의 데이터 분리 (v2.9 개정)

| 표시처 | 표시 내용 |
|---|---|
| 사용자 결과 화면 | 이해하기 쉬운 요약 지표 |
| 개인 이력 화면(SCR-023) | 함께한 날 · 전체 활동 시간 · 활동별 최근 5회 평균 |
| 관리자 화면 | 참여 횟수 · 참여 시간 · 정확하게 선택 · 평균 반응 시간 · 다른 선택 · 도움 받은 횟수 |

### 수집하되 이번 범위에서 표시하지 않는 항목

| 항목 | 처리 |
|---|---|
| 유지 시간 · 흔들림 · 좌우 편차 | **내부 측정만 하고 어느 화면에도 표시하지 않는다** |

> v2.8까지 이 항목들을 「관리자 대시보드에서 상세 분석」으로 규정했으나, 운영자가 해석할 수 없는 수치이며 파일 내보내기도 미채택(18-6)이므로 **이번 범위에서 표시 수단을 두지 않는다.**
> 1-6의 원칙대로 **비표시는 미측정을 의미하지 않는다.** 데이터는 계속 쌓이며, 필요해지면 서비스 모드(SVC) 또는 후속 범위에서 표시 수단을 정한다.

# 4. 미니게임 1: 수확하기

## 4-1. 기획 상태

수확하기는 세 게임 중 세부 규칙이 가장 구체적으로 정리된 게임이다.

## 4-2. 기본 구조

- 카테고리: 반응형 선택·팔 동작 게임
- 1라운드에서 작물 1개를 수확한다.
- 선택지는 라운드 진행에 따라 **3 → 4 → 5개**로 늘어난다 (1-9).

| 구간 | 넝쿨 수 |
|---|---|
| R1 ~ R3 | 3개 |
| R4 ~ R7 | 4개 |
| R8 ~ R10 | 5개 |

  선택지가 늘어나는 것을 사용자에게 알리지 않는다. 해당 라운드에서 자연스럽게 늘어난 상태로 제시한다.
- 정답 위치는 라운드마다 변경한다.
- 선택지는 다음 3종으로 구성한다.
  1. 목표 작물
  2. 다른 작물
  3. 벌레 먹은 작물

벌레 먹은 작물은 구멍, 벌레 표식 등 사용자가 보고 구분할 수 있는 상시 식별 요소를 가진다.

## 4-2-1. 작물 8종 (확정 · v4.4 신설)

| # | 작물 | 매달리는 자리 |
|---|---|---|
| 1 | 호박 | 넝쿨 |
| 2 | 오이 | 넝쿨 |
| 3 | 가지 | 넝쿨 |
| 4 | 토마토 | 넝쿨 |
| 5 | 고추 | 넝쿨 |
| 6 | 대추 | 가지 |
| 7 | 감 | 가지 |
| 8 | 밤 | 가지 |

| 항목 | 규칙 |
|---|---|
| 배정 | 목표 작물은 8종 중에서 고르되, 한 판 안에서 같은 작물이 **2회를 넘지 않게** 한다 |
| 벌레 먹은 작물 | 그 라운드 **목표 작물과 같은 종**이다. 종이 다르면 「다른 작물」과 역할이 겹친다 |
| 이미지 | 성한 것 8 + 벌레 먹은 것 8 = **16장**. 두 장이 한 쌍으로 제작된다 |
| 재사용 | **요리하기 재료 이미지를 재사용하지 않는다.** 형태가 다르다 |

「넝쿨」은 선택지가 매달리는 자리를 가리키는 **설계 용어**이며 사용자 화면에는 노출되지 않는다.
대추·감·밤처럼 가지에 달리는 작물을 포함하므로, 실제 표현 방법은 디자인 파트의 판단에 따른다.

수량과 라운드별 구성은 **게임 구성표**에서 함께 관리한다.

## 4-3. 라운드 흐름

```text
라운드 시작
→ 목표 넝쿨 약 1초 강조
→ 강조 종료와 함께 반응 시간 측정 시작
→ 손 커서가 넝쿨 영역에 진입
→ 손을 아래 방향으로 이동
→ 수확 판정
→ 정답 또는 다른 선택 연출
→ 다음 라운드
```

### 시작 강조

- 글로우
- 반짝임
- 아래 방향 화살표
- TTS 없음
- 전 라운드와 전 사용자에게 같은 조건으로 제공

반응 시간의 기준점 `t=0`은 시작 강조 연출이 끝난 시점이다.

## 4-4. 인식 방식

- 손가락 잡기 판정을 사용하지 않는다.
- 손목 제스처 분류기를 사용하지 않는다.
- 목표 영역 진입과 손 중심 좌표의 아래 방향 이동을 판정한다.
- 안내 문구는 `잡으세요`보다 `손을 대고 아래로 당겨 주세요` 계열을 사용한다.

### 오수확 방지 검토안

- 영역 진입 후 0.3~0.5초 무장 지연
- 하강 이동 최소 거리 적용

두 값은 개발 검증 후 확정한다.

## 4-5. 정답 연출

- 작물이 포물선으로 바구니에 들어간다.
- 밝고 경쾌한 효과음을 사용한다.
- 바구니가 반짝인다.
- TTS는 사용하지 않는다.

## 4-6. 다른 선택 연출

- 다른 작물 또는 벌레 먹은 작물을 당기면 화면 상단 대각선 방향으로 회전하며 날아간다.
- 연출 시간은 약 0.4~0.6초 검토안이다.
- 사용자 방향으로 날아오는 연출은 사용하지 않는다.
- 바람 소리와 멀리 떨어지는 작은 효과음으로 정답과 구분한다.
- 화면에 잘못 고른 작물이 계속 쌓이지 않는다.
- 라운드는 정상적으로 종료되고 실제 선택 내용은 기록한다.

## 4-7. 힌트

- 목표 제시 후 10초 동안 수확 선택이 없으면 목표 넝쿨을 다시 강조한다.
- TTS 없이 시각 강조와 부드러운 효과음만 사용한다.
- 반복 주기와 최대 횟수는 **개발 판단**이다 (12-2 C9). 최종 수치는 밸런스 문서에서 확정한다 (0-6).

## 4-8. 기록 데이터

현재 기록 대상으로 보는 항목:

- 라운드별 실제 선택 작물
- 정답·다른 작물·벌레 먹은 작물 구분
- 반응 시간
- 수행 시간
- 힌트 발동 여부

공식 데이터 항목과의 최종 매핑은 전체 규칙 확정 후 정리한다.

# 5. 미니게임 2: 장보기

## 5-1. 기획 상태 및 기준 자료

장보기는 잔치 스토리 구조를 적용하면서 교체된 게임이며, **5발판 구조로 전면 재설계되었다.**

기준 자료: 「장보기 게임 5발판 시스템·UI 인계자료 v1.0」(2026-08-04) 및 첨부 와이어프레임.
본 장은 해당 자료를 통합 수록한 것이며, 이전 v2.3.1 5장(좌/중앙/우 3분할 + 자세 유지 구조)은 **전면 폐기**한다.

## 5-2. 한 문장 정의

> 장보기는 화면 상단에 제시된 1~3개의 재료 순서에 따라, 네 개 점포와 세로로 1:1 대응하는 빛나는 발판 위치로 이동해 자연스럽게 멈추며 재료를 획득하고, 마지막에 중앙 장바구니 발판으로 복귀하는 10라운드 균형·이동 게임이다.

## 5-3. 게임 성격 (확정)

장보기는 기억력·두뇌 게임이 아니라 **균형 및 좌우 이동 중심 게임**이다.

### 주목적

- 좌우 방향으로 몸 중심 이동
- 이동 중 균형 조절
- 목표 위치까지 안전하게 이동
- 좌우 이동 범위 변화
- 현재 위치에서 다음 위치로 방향 전환

### 장보기 테마의 역할

- 점포와 재료는 이동 목적을 자연스럽게 설명하는 테마 장치다.
- 사용자가 재료 위치를 기억하거나 정답을 추론하도록 만드는 게임이 아니다.
- 현재 이동할 위치는 발판 점등으로 직접 안내한다.

### 사용하지 않는 인지 규칙

방해 재료 비교 / 정답 재료 찾기 / 재료 위치 기억 / 구매 순서 암기 / 오답 재료 선택 문제

## 5-4. 핵심 사용자 동작 (확정)

```text
목표 확인
→ 빛나는 발판으로 이동
→ 목표 위치에서 자연스럽게 멈춤
→ 재료 획득
→ 다음 목표가 있으면 다음 발판 점등
→ 모든 목표 완료
→ 중앙 발판 점등
→ 중앙 복귀
→ 장바구니 담기 연출
→ 다음 라운드
```

### 사용자 안내 문구

> 빛나는 발판으로 이동하세요

긴 설명 문장은 플레이 화면에 표시하지 않는다.

### 금지 표현 (오류 자료 재발 방지)

양발을 고정하세요 / 제자리에서 체중만 이동하세요 / 상체만 좌우로 기울이세요 / 한쪽 다리에 체중을 실으세요 / 자세를 버텨 주세요

## 5-5. 발판 및 점포 배치 (확정)

### 발판 (내부 명칭)

```text
좌외곽 / 좌안쪽 / 중앙 / 우안쪽 / 우외곽
```

실제 플레이 화면에서는 발판 아래 위치 명칭을 표시하지 않는다.

### 발판 확장 (확정 · v3.3 신설)

발판 수는 라운드 진행에 따라 **3개 → 5개**로 늘어난다 (1-9).

| 구간 | 발판 | 사용 위치 | 점포 |
|---|---|---|---|
| **R1 ~ R4** | **3개** | 좌안쪽 · 중앙 · 우안쪽 | **2개** (좌안쪽 · 우안쪽) |
| **R5 ~ R10** | **5개** | 전체 | **4개** |

| 규칙 | 내용 |
|---|---|
| 3발판 구간의 바깥 | 좌외곽·우외곽 발판과 바깥 점포를 **표시하지 않는다.** 비활성 상태로 두지 않는다 |
| 사유 | 갈 수 없는 자리가 보이면 「왜 못 가지」라는 의문을 만든다. 없으면 의문 자체가 생기지 않는다 |
| 확장 알림 | **없다.** R5가 시작될 때 조용히 5발판 상태로 제시한다 |
| 안전 관점 | 초반 4라운드 동안 좁은 범위에서 이동에 익숙해진 뒤 범위를 넓힌다 |

중앙 장바구니와 중앙 발판은 **모든 구간에서 동일한 위치**를 유지한다. 확장 시 중앙이 움직이지 않아야 기준점이 흔들리지 않는다.

### 점포 4개 + 중앙 장바구니

```text
[점포]     [점포]     [중앙 장바구니]     [점포]     [점포]
[좌외곽]   [좌안쪽]        [중앙]         [우안쪽]   [우외곽]
```

### 필수 정렬 규칙

각 점포·장바구니와 발판은 **동일한 세로축에서 1:1로 정렬**되어야 한다.

| 상단 오브젝트 | 하단 대응 발판 |
|---|---|
| 좌측 바깥 점포 | 좌외곽 발판 |
| 좌측 안쪽 점포 | 좌안쪽 발판 |
| 중앙 장바구니 | 중앙 발판 |
| 우측 안쪽 점포 | 우안쪽 발판 |
| 우측 바깥 점포 | 우외곽 발판 |

### 크기·간격 원칙

- 점포 폭은 대응 발판의 좌우 끝선과 시각적으로 맞춘다.
- 점포와 발판 사이에 불필요하게 넓은 수평 간격을 두지 않는다.
- 5개 발판은 화면 하단에 일렬로 배치한다.

## 5-6. 라운드 구조 (확정)

- 전체 라운드 수: **10라운드 고정**
- 라운드별 목표 재료 수: **1~3개**
- 라운드 순서와 목표 수 배분은 **고정**이다. 무작위로 섞지 않는다.

### 목표 수 배분 (확정)

| 구간 | 발판 | 목표 재료 수 |
|---|---|---|
| R1 ~ R2 | 3개 | 1개 |
| R3 ~ R4 | 3개 | 2개 |
| R5 ~ R7 | 5개 | 2개 |
| R8 ~ R10 | 5개 | 3개 |

전체 목표 재료는 **20개**다. 배분은 고정이며 무작위로 바꾸지 않는다.

**신체 부하 게임이므로 안전이 난이도보다 우선한다.** 앞 라운드에서 이동 자체에 익숙해진 뒤 범위와 목표 수를 늘린다.

### 목표 발판 선택 — 무작위 (확정)

> **어느 발판을 목표로 삼을지는 라운드마다 무작위로 정한다.**

고정 경로표를 두지 않는다. 매번 같은 순서로 다니면 반복 참여 시 이동을 예측하게 되어, 화면을 보지 않고 몸만 움직이는 상태가 된다.

발판 위치는 좌외곽 `L2` · 좌안쪽 `L1` · 중앙 `C` · 우안쪽 `R1` · 우외곽 `R2`로 표기한다.
모든 라운드는 중앙에서 시작하고, 목표를 모두 채운 뒤 중앙으로 복귀한다.

### 무작위 생성 제약 (확정)

무작위이되 아래 제약을 반드시 지킨다. **안전에 직결되는 규칙이다.**

| # | 제약 | 이유 |
|---|---|---|
| 1 | **좌외곽과 우외곽을 연속으로 배치하지 않는다** (`L2 → R2`, `R2 → L2` 금지) | 화면 끝에서 반대 끝까지의 장거리 왕복은 낙상 위험이 가장 큰 이동이다 |
| 2 | 한 라운드 안에서 **같은 발판을 두 번 목표로 삼지 않는다** | 이동 없이 판정만 반복되는 상황을 막는다 |
| 3 | 그 구간에서 **사용 중인 발판만** 목표로 삼는다 | R1~R4에는 외곽 발판과 바깥 점포가 존재하지 않는다 (5-5 · 5-13) |
| 4 | 한 라운드의 **외곽 발판은 최대 1개**로 제한한다 (R5 이후) | 장거리 이동이 한 라운드에 몰리지 않게 한다 |

> 무작위 추첨의 구현 방식(시드·재추첨 처리 등)은 **개발 판단**에 따른다.
> 위 4개 제약을 만족하는 결과가 나오면 방식은 자유롭다.

### 목표 표시

```text
두부 → 밀가루 → 소금
```

- 현재 목표: 가장 크고 밝게 표시
- 다음 목표: 상대적으로 작게 표시
- 그다음 목표: 더 약하게 표시 가능
- 완료한 목표: 완료 상태로 변경
- **사용자는 순서를 외울 필요가 없다.**

## 5-7. 플레이 흐름 상세 (확정)

### 라운드 시작

1. 사용자가 중앙 위치에서 시작한다.
2. 상단 목표 패널에 1~3개의 목표 재료을 표시한다.
3. 현재 목표 재료을 판매하는 점포와 대응 발판을 강조한다.
4. 목표 발판을 밝게 점등한다.

### 점포 이동

1. 사용자는 빛나는 발판 방향으로 이동한다.
2. 목표 위치까지 가는 동안 다른 발판 영역을 지나갈 수 있다.
3. **다른 발판의 단순 통과는 선택·실패로 판정하지 않는다.**
4. 목표 발판 영역에서 몸 중심 이동이 줄어들고 자연스럽게 멈추면 도착으로 확정한다.

### 재료 획득

해당 점포 반응 → 목표 재료 획득 연출 → 목표 목록 완료 상태 반영 → 다음 목표 강조 (없으면 중앙 발판 강조)

### 중앙 복귀

좌우 발판 강조 종료 → 중앙 발판 점등 → 중앙 복귀 → 장바구니 담기 연출 → 라운드 완료 → 다음 라운드

## 5-8. 판정 시스템 원칙 (확정)

### 위치 판정

- 발 또는 발목을 직접 추적하지 않는다.
- **발바닥 아이콘은 사용하지 않는다.**
- 골반 또는 몸통 중심의 가로 위치를 기준으로 판정한다.
- 실제 판정 영역은 사용자 초기 보정값을 기준으로 설정한다.
- 화면 발판은 실제 발 위치 데이터가 아니라 **사용자 이동 위치를 안내하는 UI**다.

### 통과와 도착 구분

```text
발판 영역에 들어왔지만 계속 이동 중 → 통과 → 판정 없음
발판 영역에서 이동 속도가 낮아지고 멈춤 → 도착 → 구매 판정
```

### 정지 판정

- 자세 유지 운동으로 해석하지 않는다.
- 한쪽 다리에 체중 싣기를 요구하지 않는다.
- **유지 게이지를 사용하지 않는다.**
- 흔들림 정도를 성공 조건으로 사용하지 않는다.
- 지나가는 중인지 도착한 것인지를 구분하는 최소 판정만 사용한다.
- 정확한 정지 시간과 속도 기준은 프로토타입 테스트 후 결정한다.

### 구매 후 재판정 잠금 (확정 · v2.7 신설)

한 발판에서 구매가 확정되면 **그 발판을 벗어나기 전까지 다시 판정하지 않는다.**
같은 라운드에서 이미 구매한 점포도 재판정 대상에서 제외한다.

**사유** — 고령 사용자는 재료를 산 뒤 곧바로 다음 발판으로 옮기지 않는다. 잠시 서서
화면을 확인하고 다음 목표를 파악한 뒤 움직이는 것이 자연스럽다. 이 잠금이 없으면
그 자연스러운 멈춤이 곧바로 다음 판정으로 이어져, 서 있기만 해도 원치 않는 구매가 발생한다.

| 상태 | 판정 |
|---|---|
| 구매 직후 같은 발판에 머무름 | 판정하지 않음 |
| 해당 발판을 벗어남 | 잠금 해제 |
| 이미 구매한 점포로 되돌아옴 | 판정하지 않음 |

구매가 완료된 점포에는 시각 표시를 붙여 무엇을 이미 샀는지 알 수 있게 한다.

## 5-8-1. 자동 힌트 (확정)

### 발동 조건

> **목표 발판이 점등된 뒤 몸 중심의 좌우 이동이 10초 동안 없을 때 발동한다.**

| 안 | 채택 여부 | 사유 |
|---|---|---|
| 몸 중심 좌우 이동 없음 | **채택** | 「움직이지 않는 상태」만 정확히 잡는다 |
| 10초간 목표 발판 미도착 | 미채택 | 천천히 걷는 사용자에게 부당하게 발동한다 |
| 다른 위치에서 10초 이상 정지 | 미채택 | 구매 후 재판정 잠금 중 서 있는 정상 상태에 걸린다 |

> 「좌우 이동」의 판정 방식과 임계값은 **개발 판단**에 따른다.
> 구현이 어렵거나 공수가 과다하면 기존 방식 또는 개발팀 추천 방식으로 수정 가능하다.

### 힌트가 전달할 것

장보기는 **목표 발판이 이미 점등되어 있다.** 따라서 수확하기·요리하기와 전달 내용이 다르다.

| | 수확하기 · 요리하기 | **장보기** |
|---|---|---|
| 힌트가 전달할 것 | 무엇이 정답인가 | **움직여야 한다** |

목표를 다시 알려주는 것이 아니라 **이동을 유도**해야 한다. 표현 방식은 디자인 파트의 판단에 따른다.

### 해제 조건

- 몸 중심의 좌우 이동이 감지되면 즉시 해제한다.
- 해제 후 다시 10초 동안 이동이 없으면 같은 방식으로 재발동한다.
- 힌트 발동 후 도착한 경우도 **정상 구매로 처리**한다(3-2 공통 원칙).
- 발동 횟수는 내부 데이터로만 기록한다.

### 표현 금지

- TTS 사용 금지 (플레이 중)
- 재촉·독촉으로 읽히는 표현
- 남은 시간 표시

## 5-9. 화면 UI 구성 (확정)

기준 해상도 1920×1080, 16:9 전용. 실제 게임에 들어갈 UI만 표현하며 설명용 인물·관절 포즈·외부 주석은 플레이 화면에서 제외한다.

| 영역 | 내용 |
|---|---|
| 하단 중앙 | 일시정지 버튼 |
| 상단 중앙 | 현재 라운드의 목표 재료 순서 패널 (아이콘 + 한글 재료명, 현재 목표 최강조) |
| 상단 우측 | 경과 시간 표시 **(확정 · 유지)**. 시간 제한 게임이 아니며 재촉 표현을 함께 두지 않는다 |
| 우측 세로 | 1~10 라운드 진행 레일, 현재 라운드 강조. **상단 가로 단계 표시는 두지 않는다**(중복 배치 금지) |
| 중앙 | 좌측 점포 2 + 중앙 장바구니 + 우측 점포 2, 짧은 안내 문구 |
| 하단 | 발판 5개. 위치 텍스트·발바닥 아이콘 없음. 목표 발판은 테두리·밝기·점등으로 구분. 중앙 발판은 복귀 단계에서 점등 |

### 점포 내부 상품 표현

- 상품을 복잡한 진열 이미지로 상세하게 그리지 않는다.
- 점포 내부에 **큰 네모형 상품 카드 1개**를 배치하고 그 안에 단순화한 상품 아이콘을 표시한다.
- 상품 카드 아래 또는 점포 하단에 한글 상품명·분류명을 표시한다.
- 실제 화면에서 `점포 1`, `점포 2` 등 번호 명칭은 표시하지 않는다.

### 화면 표현 규칙 (v2.5 확정)

와이어프레임 검토 과정에서 발판이 화면을 누르는 선택 버튼처럼 읽히는 문제가 확인되어 아래를 확정한다.

| 항목 | 규칙 |
|---|---|
| 바닥면 | 발판 아래에 **바닥면을 명시적으로 표현**한다. 발판이 허공에 뜬 UI로 보이지 않게 한다 |
| 발판 형태 | **윗면 + 앞면 측면을 가진 입체 발판**으로 표현한다. 평평한 둥근 사각형(버튼 형태)을 사용하지 않는다 |
| 시점 | 바닥을 비스듬히 내려다보는 시점으로 표현한다 |
| 목표 발판 강조 | 발판 위쪽 공중에서 **발판을 가리키는 아래 방향 표시**를 사용한다. 손 동작 지시와 혼동되지 않게 한다 |
| 중앙 발판 | 시작·복귀 자리임이 드러나도록 다른 발판과 구분되는 표시를 둔다 |
| 점포 | **지붕 표현을 사용하지 않는다.** 크기를 과장하지 않고 발판보다 시각 비중을 낮춘다 |
| 점포 상품명 | 목표 안내는 발판 점등에 의존한다. 상품명은 보조 정보 수준으로만 표시한다 |

이 규칙의 목적은 장보기가 **몸으로 좌우 이동하는 게임**임을 화면만 보고도 알 수 있게 하는 것이다.

## 5-10. 제외·폐기된 방향

### 조작 관련

양발 고정 / 제자리 체중 이동 / 상체만 좌우 기울이기 / 한쪽 다리에 체중 싣기 / 1~2초 자세 버티기 / 자세 유지 게이지 / 흔들림을 성공 조건으로 평가 / 팔로 원 만들기 / 팔로 장바구니 모양 만들기 / 별도의 구매 확정 팔 동작 / 발·무릎 직접 추적

### 발판 구조 관련

V자형 발판 배치 / 매 재료 획득 후 중앙으로 반복 복귀하는 구조 / 이동 중 다른 발판 진입 즉시 구매 또는 실패 판정

> **주의 — 「3발판」 자체는 폐기 대상이 아니다.**
> 폐기한 것은 구 5장의 **좌·중앙·우 3분할 + 체중 싣기 + 자세 유지 게이지** 조작 방식이다.
> 현행 R1~R4 구간의 3발판은 **5발판 구조의 축소 상태**이며, 조작 방식은 5발판 구간과 완전히 동일하다(몸 전체 이동 + 도착 판정).

### UI 관련

하단의 긴 설명 텍스트 바 / 튜토리얼 설명을 플레이 내내 크게 표시 / 상단과 우측의 중복 진행 표시 / 발판 아래 위치 텍스트 / 점포 번호 표시 / 발바닥 아이콘 / 복잡한 시장 진열물 표현 / 우측 별도 장보기 목록 패널 / 우측 별도 장바구니 패널

## 5-11. 확정 사항과 개발 판단 항목

### 다른 점포에서 멈춘 경우 (확정)

**그 점포의 재료를 그대로 구매하고, 중앙으로 복귀한 뒤 다음 라운드로 진행한다.**

- 실패 판정을 하지 않는다. 라운드를 중단하거나 되돌리지 않는다.
- 구매한 재료는 장바구니에 담기고 결과 화면에 그대로 표시된다.
- 3-3 다른 선택 처리 원칙과 동일한 구조다. 사용자의 선택은 수용되고, 실제로 한 일이 결과에 정직하게 남는다.
- 사용자 대면 표기는 "실패"가 아니라 **"다르게 산 재료"**으로 한다.

### 기획 결정 — **0건**

라운드 배분·이동 경로(5-6) · 자동 힌트(5-8-1) · 경과 시간 표시(5-9) · 재료·점포 구성(5-13) · 결과 데이터(5-14)가 확정되어
장보기의 기획 결정 항목은 없다.

### 개발 판단 항목

아래는 개발팀 판단에 따른다. 구현이 어렵거나 공수가 과다하면 **기존 방식 또는 개발팀 추천 방식으로 수정 가능**하다.

| # | 항목 | 기획이 요구하는 것 |
|---|---|---|
| 1 | 도착 판정 기준값 (목표 영역 크기 · 몸 중심 속도 · 정지 인정 시간 · 경계 흔들림 방지 · 히스테리시스) | 지나가는 중에는 판정하지 않고, 발판 위에 잠깐 멈춘 것을 도착으로 볼 것 |
| 2 | 실제 이동 범위와 안전 한계 (안쪽·외곽 거리, 외곽 간 이동 허용 여부) | 5-6의 무작위 생성 제약을 안전하게 수행할 수 있는 범위일 것 |
| 3 | 자동 힌트 「좌우 이동」 판정 방식 | 몸 흔들림만으로 해제되지 않을 것 |
| 4 | 사용자 현재 위치 표시 방식 | 자기 위치를 알 수 있을 것 (12-2 C6) |

### 콘텐츠 자산 — **확정**

재료·점포 구성은 5-13에서 확정했다. 요리하기 재료 풀 22종을 그대로 사용하며 신규 재료 도안은 없다.
남은 자산은 **점포 이미지 4종**이다.

## 5-12. 프로토타입 검증 체크리스트

### 판정

- 중간 발판 통과가 구매로 오인되지 않는가
- 목표 발판에서 자연스럽게 멈추면 안정적으로 구매되는가
- 발판 경계에서 판정이 빠르게 반복되지 않는가
- 중앙 통과와 중앙 복귀를 구분할 수 있는가

### 안전

- 좌외곽·우외곽 이동 범위가 과도하지 않은가
- 외곽 간 이동 시 보폭이 지나치게 커지지 않는가
- 1~3개 목표 구성에서 피로가 과도하지 않은가
- 장거리 왕복 경로가 연속 배치되지 않는가

### UI 이해도

- 점포와 발판이 수직으로 대응된다는 것을 즉시 이해하는가
- 현재 목표 재료과 현재 목표 발판을 쉽게 찾는가
- 다음 목표 미리보기가 혼란을 주지 않는가
- 중앙 장바구니와 중앙 복귀의 의미를 이해하는가
- 우측 진행 레일만으로 현재 라운드를 확인할 수 있는가

### 연출

- 목표 점포와 목표 발판의 강조가 함께 반응하는가
- 재료 획득 피드백이 명확한가
- 마지막 중앙 복귀가 라운드 완료로 자연스럽게 느껴지는가

## 5-13. 재료 및 점포 구성 (확정 · v3.4 신설)

### 기본 원칙

> **장보기에서 사는 재료는 요리하기 재료 풀 22종(6-13-5) 안에서 고른다.**

전용 재료를 따로 만들지 않는다. 「시장에서 산 재료로 요리한다」는 스토리가 실제로 이어지고, **재료 이미지를 그대로 재사용**하므로 신규 도안이 발생하지 않는다.

### 장보기에 등장하지 않는 재료 2종

| 재료 | 사용처 | 제외 사유 |
|---|---|---|
| 밥 | 김밥 | 시장에서 사는 물건이 아니다 |
| 솔잎 | 송편 | 시장 진열 재료로 어색하다 |

두 재료는 **요리하기 재료 풀에는 그대로 남는다.** 장보기 대상에서만 빠진다.
따라서 장보기 대상 재료는 **20종**이다.

### 점포 4곳 — 위치 고정 (확정)

```text
[방앗간]   [채소 가게]   [장바구니]   [정육점]   [건어물·반찬 가게]
[좌외곽]    [좌안쪽]      [중앙]      [우안쪽]      [우외곽]
```

| 위치 | 점포 (표시 명칭 · 기준안) | 취급 재료 | 수 |
|---|---|---|---|
| 좌외곽 | 방앗간 | 쌀가루 · 밀가루 · 팥 · 깨 · 밤 | 5 |
| 좌안쪽 | 채소 가게 | 호박 · 시금치 · 당근 · 파 · 버섯 | 5 |
| 우안쪽 | 정육점 | 소고기 · 갈비 · 달걀 · 두부 | 4 |
| 우외곽 | 건어물·반찬 가게 | 미역 · 김 · 김치 · 간장 · 당면 · 곶감 | 6 |

> **확정 대상은 「어느 위치에 어떤 재료 묶음이 있는가」다.**
> 점포의 **표시 명칭은 기준안**이며, 자산 제작 단계에서 그림과 함께 조정할 수 있다.
> 명칭이 바뀌어도 위치와 취급 재료 구성은 유지한다.

- **점포 종류와 위치는 고정**이다. 라운드마다 바뀌지 않는다.
- 같은 자리에 늘 같은 가게가 있어야 반복 참여 시 공간 기억이 쌓인다.
- 3발판 구간(R1~R4)에는 **채소 가게와 정육점만** 등장한다. 바깥 두 점포는 표시하지 않는다(5-5).
- 실제 화면에 「점포 1」 같은 번호 명칭을 쓰지 않는다. 가게 이름으로 표시한다.

### 진열 규칙 (확정)

| # | 규칙 |
|---|---|
| 1 | 라운드 시작 시 각 점포에 **그 점포 취급 재료 중 1종**을 진열한다 |
| 2 | 한 라운드 안에서 같은 재료가 두 점포에 중복 진열되지 않는다 |
| 3 | 한 판(10라운드) 안에서 같은 재료가 **3회를 넘지 않게** 한다 |
| 4 | 진열 재료 선택은 무작위이며, 목표 발판 선택(5-6)과 함께 결정된다 |

> 무작위 추첨의 구현 방식은 **개발 판단**에 따른다. 위 3개 제약을 만족하면 방식은 자유롭다.

3번 규칙을 두는 이유는 SCR-014의 **종류 묶음 + 개수 배지** 표현 때문이다. 반복이 전혀 없으면 배지가 항상 1이 되어 묶음 표현이 무의미해지고, 반복이 과하면 결과가 단조로워진다.

### 요리하기와의 관계 — 연출상 연결 (중요)

> **장보기에서 산 재료가 요리하기 라운드에 데이터로 넘어가지 않는다.**

두 게임은 각각 독립된 10라운드다. 스토리 모드에서 「시장에서 재료를 사 왔다 → 그 재료로 요리한다」로 이어 보이는 것은 **테마와 연출의 연결**이며, 실제 재료 데이터를 주고받지 않는다.

데이터를 연동하면 장보기에서 다르게 산 재료 때문에 요리하기 레시피가 성립하지 않는 라운드가 생긴다. 두 게임의 판정이 서로를 무너뜨리지 않도록 분리한다.

### 필요 자산

| 자산 | 수량 | 비고 |
|---|---|---|
| 재료 이미지 | 0 | **요리하기 22종 재사용** |
| 점포 이미지 | **4종** | 방앗간 · 채소 가게 · 정육점 · 건어물·반찬 가게 |
| 장바구니 이미지 | 1 | 중앙 |

점포 이미지는 **지붕을 그리지 않고**, 발판보다 시각 비중을 낮춘다(5-9). 가게마다 구분되도록 제작하되 표현 방법은 디자인 파트의 판단에 따른다.

## 5-14. 결과 데이터 및 결과 화면 (확정)

### 두 가지 집계 단위

장보기는 **재료 단위**와 **라운드 단위**를 함께 쓴다. 쓰이는 곳이 다르다.

| 단위 | 총량 | 쓰이는 곳 |
|---|---|---|
| **재료** | **20개** (5-6 목표 수 배분 합계) | SCR-014 개별 결과 카드 · 장바구니 나열 |
| **라운드** | **10회** | SCR-022 최종 잔치상 · SCR-023 개인 이력 · ADM 통계 |

**라운드 성공** = 그 라운드의 재료를 **전부** 제대로 구매한 경우다(9-1).
결과 화면은 사용자가 실제로 담은 재료를 보여주는 자리이므로 재료 단위가 자연스럽고,
게임 간 비교가 필요한 곳은 세 게임이 모두 10인 라운드 단위를 쓴다.

### SCR-014 개별 결과 — 요약 카드 3종

| 카드 | 값 | 산출 |
|---|---|---|
| **제대로 산 재료** | `n 개` | 목표 점포에서 구매한 재료 수 |
| **다르게 산 재료** | `n 개` | 다른 점포에서 구매한 재료 수 |
| 전체 활동 시간 | `n분 n초` | 일시정지 시간 제외 |

- 두 값의 합은 항상 **20**이다. 분모는 카드에 표기하지 않는다.
- 힌트를 받고 도착한 경우도 **제대로 산 재료에 포함**한다.
- **「잘못 산」·「틀린」 등 평가 표현을 쓰지 않는다.** 사용자 대면 표기는 「다르게 산」으로 통일한다(5-11 · 8-6).

### SCR-014 — 재료 나열

| 항목 | 규칙 |
|---|---|
| 단위 | **종류 단위 묶음 + 개수 배지** (8-2 준용) |
| 구분 | 위·아래 위치 + 기울임 · 위 = 제대로 산 재료 / 아래 = 다르게 산 재료 |
| 라운드 번호 | **표시하지 않는다** — 라운드당 재료 수가 가변이라 대응이 성립하지 않는다 |

### SCR-015 간이 결과

| 항목 | 규칙 |

| 다음 화면 | SCR-016 연결 연출 2 |

### 표시하지 않는 것

### 6-0-1. 작업 영역 구분 (신설 · 본 장 전체에 적용)

> **기획은 「무엇이 필요한가」와 「왜 필요한가」를 정한다. 「어떻게 만들 것인가」는 각 파트에 맡긴다.**

|---|---|---|

| **디자인** | 무엇이 보여야 하는가 · 무엇이 구분되어야 하는가 · 하면 안 되는 표현 | 화풍 · 색 · 연출 방식 · 타이밍 · 도안 형태 · 검수 절차 |

본 장에서 수치나 형태가 적힌 항목은 **기준안**이거나 **와이어프레임에서 이미 확정된 좌표**다. 각 파트가 더 나은 방법을 제안하면 그쪽을 따른다.

## 6-1. 게임 정체성 (확정)

요리하기는 조리 시뮬레이션이 아니라 **시각 기억 게임**이다.

```text
완성 음식과 필요한 재료 확인
→ 레시피 숨김
→ 후보 재료 중 기억한 재료 선택
→ 필요한 개수만큼 담기
→ 일괄 판정
```

### 핵심 조작으로 사용하지 않는 것

칼질 / 뒤집기 / 젓기 / 반죽하기 / 불 조절 / 요리 순서 맞추기 / 조리 시간 맞추기 / 완성 음식을 직접 조작하는 행동

잔치 음식은 테마와 보상 표현이며, 핵심 인지 과제는 **필요한 재료 기억**이다.

## 6-2. 라운드 흐름 (확정)

### 라운드 구성

- 총 **10라운드 고정** (1-7 공통 원칙)
- 라운드마다 음식 **1종**을 완성한다
- 음식 10종을 **1회씩** 사용하므로 한 판 안에서 음식이 중복되지 않는다
- 라운드 순서는 **고정**이다 (6-13)

### 레시피 기억 단계 (SCR-018-1)

레시피 기억 단계는 **팝업(오버레이) 형태**로 표시하며, 화면 번호 SCR-018-1로 등재한다.

| 항목 | 규칙 |
|---|---|
| 형태 | SCR-018 위에 얹히는 오버레이 팝업 |
| 배경 | **불투명 차폐** — 뒤의 후보 재료가 비쳐 보이면 기억 과제가 대조 과제로 바뀌므로 반드시 가린다 |
| 공통 HUD | 팝업 중에도 유지한다 |
| 조작 | 팝업 표시 중 재료 선택 불가 |
| 재사용 | 라운드 시작과 차림표 다시 보기에 **동일 팝업**을 사용한다 |
| 종료 | 「다 외웠어요」 선택 시 닫히고 재료 선택 상태로 복귀한다. 담은 재료 상태는 유지된다 |

- 완성 음식 이미지와 필요한 재료를 **함께** 표시한다.
- 재료는 라운드에 따라 **1~3개**를 사용한다.
- 팝업이 닫히면 완성 음식 이미지와 정답 재료를 모두 숨긴다.

### 재료 선택 단계 (SCR-018)

- 상단 문구: `기억한 재료를 선택해 주세요`
- 상단 목표 패널에 **음식 이름을 계속 표시**한다. 예: 「잡채」에 넣을 재료를 골라 주세요
- 후보 재료 **6개**를 3×2로 배치한다.
- 후보 재료 영역이 **유일한 선택 가능 영역**이다.
- 담은 재료 영역은 **비인터랙션 상태 표시**다. 호버·게이지·재선택 반응 없음, 취소 버튼 없음.
- 수동 힌트 버튼은 두지 않는다.

### 선택 순서 (확정 · 신설)

> **재료를 고르는 순서는 판정에 영향을 주지 않는다.**

레시피에 적힌 순서대로 고를 필요가 없다. 어떤 순서로 담아도 구성이 같으면 완성으로 판정한다.

**사유** — 순서까지 요구하면 과제가 「재료 기억」에서 「재료 기억 + 순서 기억」으로 이중화된다.
①·② 두 게임이 이미 순서·시간 압박을 두지 않는 기조로 확정되어 있으므로 ③만 순서를 요구하면 조작 문법이 어긋난다.

### 누적과 판정 (확정)

- 담은 재료 슬롯 수는 **그 라운드에 필요한 재료 수와 같다.**
- 선택한 재료는 **정답 여부와 무관하게 모두 슬롯에 누적**한다.
- **선택 취소와 교체는 하지 않는다.**
- 틀린 재료를 즉시 돌려보내거나 다시 선택하게 하지 않는다.
- 슬롯이 **다 차면 일괄 판정**한다.
- 다른 재료가 하나라도 포함되면 해당 라운드는 정답과 다른 것으로 처리한다.
- 강제 재도전 없음, 자동 완성 없음.
- 판정 표현(6-8) 종료 후 다음 라운드로 이동한다.

## 6-3. 입력 판정 (확정)

| 항목 | 기준 |
|---|---|
| 방식 | 손 커서가 재료 영역에 진입 → 유지 → 원형 게이지 완료 → 선택 확정 |
| 유지 시간 | **1~2초 사이** — 기준안. 실제 카메라 인식 테스트 후 확정 |

## 6-4. 시간 규칙 (확정)

| 항목 | 기준 |
|---|---|
| 최초 레시피 공개 | 재료 수 비례 (아래) |
| 차림표 다시 보기 | 5초 |
| 플레이 제한 시간 | **없음** |
| 자동 힌트 발생 | 유효한 선택 행동 10초 없음 |
| 손 체류 선택 | 1~2초 · 기준안 |

### 레시피 공개 종료 방식 (확정)

**공개 시간이 지나도 팝업을 자동으로 닫지 않는다.** 「다 외웠어요」를 선택해야 닫힌다.

| 항목 | 규칙 |
|---|---|
| 공개 시간 | 재료 수에 비례 — **1개 3.5초 / 2개 5초 / 3개 6.5초** |
| 공개 중 | 게이지가 줄어들며 남은 시간 표시 |
| 공개 후 | 자동으로 닫히지 않고 **「다 외웠어요」 대기** |
| 버튼 | 팝업 **중앙 하단** x620 y888 440×96 · dwell 2초 |
| 게이지 | 버튼 바로 위 x520 y842 640×26 |

**사유** — 정해진 시간 안에 외우게 하면 시간 압박이 생긴다. 빨리 외운 사람은 바로 넘어가고 천천히 볼 사람은 충분히 보도록 해, 개인 속도를 존중하면서 시간 압박을 없앤다. 시간 압박 없음은 본 시스템의 기본 설계 원칙이다.

### 레시피 기억 중 일시정지 (확정)

**팝업 표시 중에는 일시정지를 사용할 수 없다.** 일시정지 버튼은 차폐면 아래에 두어 보이지도, 눌리지도 않게 한다.

경과 시간과 진행 레일 같은 **표시 요소는 그대로 유지**하되, 조작 요소만 차단한다. 기억하는 짧은 순간에 다른 조작이 끼어들면 기억이 끊기고, 실수로 눌렀을 때 불안을 준다.

## 6-5. 자동 힌트 (확정)

### 발생 조건

일반적인 몸·손 움직임이 아니라 **선택으로 이어질 수 있는 유효 행동**이 10초 동안 없을 때 발생한다. 단순 몸 흔들림이나 재료와 무관한 위치의 움직임으로 타이머가 해제되지 않는다.

> 「유효 행동」의 판정 방식은 **개발 판단**에 따른다. 구현이 어렵거나 공수가 과다하면 기존 방식 또는 개발팀 추천 방식으로 수정 가능하다.

### 안내 대상

아직 선택하지 않은 정답 재료 중 **목록상 가장 첫 번째 재료**를 알려준다.

### 표현

- 정답 재료의 테두리를 밝게 강조하고 빛 효과를 **지속 유지**한다. 짧게 점멸 후 사라지지 않는다.
- TTS 없음.

### 해제 조건

- 힌트 재료를 선택하면 강조 종료
- 다른 재료를 선택하면 강조 즉시 취소 후 10초 타이머 재시작
- 다시 10초간 유효 행동이 없으면 남은 정답 중 첫 번째 재료를 같은 방식으로 안내

힌트 발동 후 성공도 **정답으로 처리**한다 (3-2 공통 원칙). 발동 횟수는 내부 데이터로만 기록한다.

## 6-6. 차림표 다시 보기 (확정)

```text
차림표 다시 보기 선택 → 선택 화면 일시 중단 → 완성 음식과 정답 재료 표시 → 5초 → 선택 화면 자동 복귀
```

- 사용 횟수 **제한 없음**
- 최초 레시피 기억 화면과 동일한 정보 구성
- 다시 보기 중 재료 선택 불가
- 이미 담은 재료 상태는 유지
- 사용 횟수는 내부 데이터로만 기록

### 종료 방식 (확정)

**차림표 다시 보기는 5초 자동 복귀를 유지한다.** 최초 레시피 기억 화면(SCR-018-1)의 「다 외웠어요」 방식과 통일하지 않는다.

| 화면 | 종료 방식 |
|---|---|
| SCR-018-1 최초 레시피 기억 | **「다 외웠어요」** 확인 |
| 차림표 다시 보기 | **5초 자동 복귀** |

최초 공개는 외울 시간을 사용자가 정해야 하지만, 다시 보기는 이미 한 번 본 정보를 확인하는 것이므로
버튼을 한 번 더 누르게 할 이유가 없다.

## 6-7. 완성 음식 이미지 사용 범위 (개정)

| 구분 | 화면 |
|---|---|
| **사용한다** | 레시피 기억 단계(SCR-018-1) · 개별 결과(SCR-019) · **간이 결과(SCR-020)** |
| **사용하지 않는다** | 재료 선택 화면 / 담은 재료 누적 과정 / 자동 힌트 / 차림표 버튼 / 라운드 판정 피드백 / 진행 레일 |

**개정 사유** — 본 조항의 취지는 **플레이 중에 정답 단서를 노출하지 않는 것**이다. SCR-020은 플레이가 끝난 뒤의 화면이므로 취지에 걸리지 않으며, 8-3이 SCR-020에 완성 음식 표시를 요구하고 있어 문서 간 불일치가 있었다.

## 6-8. 판정 표현 (개정 · 연출 신설)

### 6-8-1. 담기는 순간의 표현 (신설 · 필수 전제)

> **재료가 담기는 순간에는 정답과 오답을 구분하지 않는다.**

담길 때 다른 반응을 주면 그 자리에서 정답을 알려주는 셈이 되어, **일괄 판정 구조와 기억 과제가 동시에 무너진다.**

| 시점 | 표현 |
|---|---|
| 재료 담김 | 재료가 냄비로 들어가 슬롯에 자리잡음 · 짧은 「톡」 소리 · **정오답 구분 없음** |

### 6-8-2. 판정 표현 요건 (신설)

슬롯이 다 차면 라운드 판정 결과를 사용자에게 전달한다. 기획이 요구하는 것은 아래 3가지다.

| # | 요건 | 이유 |
|---|---|---|
| 1 | 정답 재료와 다른 재료가 **구분되어 보일 것** | 판정 결과를 알 수 있어야 한다 |
| 2 | **어느 재료가 달랐는지** 사용자가 확인할 수 있을 것 | 결과만 알면 다음 라운드의 회상에 도움이 되지 않는다 |
| 3 | 라운드 전체 결과(완성 / 다른 재료 포함)가 전달될 것 | — |

| 문구 | |
|---|---|
| 전부 정답 | `맛있는 요리가 완성되었어요` |
| 다른 재료 포함 | `다른 재료가 들어갔어요` |

> **연출 방식 · 타이밍 · 효과음은 디자인 파트의 판단에 따른다.** 아래 6-8-3 · 6-8-4 항목만 지키면 된다.

### 6-8-3. 색상 구분 원칙 (유지)

라운드 판정 결과는 **색상 계열로만 구분**한다.

| 구분 | 표현 |
|---|---|
| 정답 일치 | 초록 계열 강조 |
| 다른 재료 포함 | 주황·갈색 계열 강조 |

- 진행 레일에 라운드 결과를 색상으로 표시하고 **X 표시를 넣지 않는다.**
- 완성 음식 이미지는 판정 순간에 표시하지 않는다.

### 6-8-4. 금지 (유지)

| 금지 |
|---|
| X 아이콘 · 빗금 · 큰 경고 기호 |
| 탄 음식 · 상한 음식 · 망가진 접시 이미지 |
| 부저음 · 하강 실패음 |
| 채도 저하 · 흑백 처리 |
| 「틀렸습니다」 등 비난 표현 |

> 본 문서 3-4의 「색상만으로 구분하지 않는다」 조항은 수확하기·장보기의 수집물 나열에 적용되며, 요리하기의 라운드 판정에는 본 항목이 우선한다. 저시력 사용자를 위해 색 대비를 충분히 확보한다.

## 6-9. 결과 데이터 및 결과 화면 (확정 · 신설)

### 6-9-1. 판정 단위

> **요리하기의 판정 단위는 「재료 개수」가 아니라 「라운드(음식)」다.**

재료 수가 1~3개 가변이므로 재료 단위로 집계하면 라운드마다 분모가 달라진다. **음식 단위 = 10개 고정**이 유일하게 일관된 단위이며, 이 값이 최종 잔치상(SCR-022)의 3게임 평균 판정에 그대로 입력된다.

### 6-9-2. SCR-019 개별 결과 — 상단 요약 카드 3종

| # | 카드명 | 값 | 산출 |
|---|---|---|---|
| 1 | **완성한 음식** | `n 가지` | 담은 재료가 정답과 전부 일치한 라운드 수 (0~10) |
| 2 | **다른 재료가 들어간 음식** | `n 가지` | 하나라도 다른 재료가 포함된 라운드 수 |
| 3 | **전체 활동 시간** | `n분 n초` | **일시정지 시간 제외** |

- 1번 + 2번 = 항상 10
- 분모 `/10`은 카드에 표기하지 않는다 (SCR-009 · SCR-014와 동일)
- 힌트를 받고 성공한 라운드도 **완성한 음식에 포함**한다

### 6-9-3. SCR-019 개별 결과 — 음식별 나열

| 항목 | 규칙 |
|---|---|
| 단위 | 라운드 1개 = 음식 카드 1장 · **총 10장** |
| 배치 | **위·아래 2단 분리** — 위 `완성한 음식` · 아래 `다른 재료가 들어간 음식` (8-2) |
| 슬롯 | 각 단에 **10칸 고정** · 남는 칸은 비워 둔다. 빈 칸은 실제 화면에 표시하지 않는다 |
| 순서 | 각 단 안에서 **라운드 순서대로** 왼쪽부터 채운다 |
| 구분 | **색상 계열 + 카드 내 문구**로 구분 — 완성 = 초록 계열 / 다른 재료 = 주황·갈색 계열 |
| 카드 내용 | 완성 음식 이미지 + 음식 이름 + 결과 문구(`완성` / `다른 재료가 들어갔어요`) |
| 라운드 번호 | **표시하지 않는다** — 음식 10종이 서로 달라 이름 자체가 식별자다 |
| 묶음 배지 | **사용하지 않는다** — 음식 10종이 1회씩만 등장하므로 중복이 없다 |

> **8-2의 위·아래 분리를 요리하기에도 적용한다. (v4.9 변경)**
> 완성 수와 다른 재료 수는 회차마다 달라지지만(7:3, 4:6 등), **각 단에 10칸 슬롯을 고정**하고
> 남는 칸을 비워 두면 컨테이너 크기가 흔들리지 않는다. 간이 결과(SCR-020)가 이미 쓰는 방식이다.
>
> 같은 게임의 개별 결과와 간이 결과가 서로 다른 구조를 쓰면, 스토리 모드에서 익힌 화면을
> 개별 모드에서 다시 익혀야 한다. **구조는 같게 두고 버튼 유무로만 구분한다.**
>
> 단 색상만으로 구분하지 않는다. 단 제목(`완성한 음식` / `다른 재료가 들어간 음식`)이
> 문구 역할을 하므로 3-4 원칙을 지킨다. 카드 안에 개별 결과 문구를 따로 넣지 않는다.

### 6-9-4. SCR-019 개별 결과 — 문구·버튼

- 문구: `요리를 마쳤어요` / `만드신 음식을 살펴보세요`
- 버튼 3종: **다시 하기 · 콘텐츠 선택 · 내 기록 보기** · 전부 dwell 3초

### 6-9-5. SCR-019에 표시하지 않는 것

| 항목 | 사유 |
|---|---|
| 자동 힌트 발생 횟수 | 상세 수치는 **ADM 전용** (8-4 표시 금지) |
| 차림표 다시 보기 횟수 | 동일 |
| 반응 시간 · 손 체류 시간 | 동일 |
| 어떤 재료가 달랐는지 | 재료 수준까지 되짚으면 지적으로 읽힌다 |
| 점수 · 등급 · 순위 · 퍼센트 | 공통 금지 |

### 6-9-6. SCR-020 간이 결과

| 항목 | 규칙 |
|---|---|
| 수치 | **전부 없음** (8-4 간이 결과 공통 원칙) |
| 버튼 | 없음 · 자동 진행 |
| 나열 | 완성 음식이 **순차 등장** · 위·아래 2단 분리 — **SCR-019와 같은 구조** |
| 라운드 번호 | **표시하지 않는다** |
| 문구 | `음식이 다 되었어요` / `이제 상을 차려 볼까요?` |
| 다음 화면 | SCR-021 엔딩 스토리 영상 |

> 자동 진행 시간(6초 기준안)과 일시정지 미제공은 8-4 공통 원칙을 따른다.

### 6-9-7. 계층별 데이터 정리표

| # | 데이터 | 내부 기록 | SCR-019 | SCR-020 | ADM | SCR-023 |
|---|---|:-:|:-:|:-:|:-:|:-:|
| 1 | 라운드 판정 결과 (10건) | ● | ● | ● | ● | ● |

| 5 | 라운드 전체 수행 시간 | ● | – | – | ● | – |
| 6 | 자동 힌트 발생 횟수 | ● | – | – | ● | – |

STATE_AUTO_HINT
  ├ 힌트 재료 선택 → STATE_INGREDIENT_SELECT
  └ 다른 재료 선택 → 힌트 취소 후 STATE_INGREDIENT_SELECT

STATE_RECIPE_REVIEW  (차림표 다시 보기 — 최초 공개와 종료 방식이 다르다)
  └ 5초 자동 복귀 → 기존 선택 상태 유지하고 STATE_INGREDIENT_SELECT

STATE_ROUND_JUDGEMENT
  ├ 전체 일치 → STATE_ROUND_COMPLETE
  └ 불일치 포함 → STATE_ROUND_DIFFERENT

STATE_ROUND_COMPLETE / STATE_ROUND_DIFFERENT
  ├ 다음 라운드 있음 → STATE_RECIPE_MEMORY
  ├ 개별 모드 종료 → SCR-019
  └ 스토리 모드 종료 → SCR-020 간이 결과

## 6-13. 레시피 구성 (확정 · 전면 신설)

### 6-13-1. 구성 원칙

**음식과 재료를 실제 관계로 묶는다.** 무작위 조합을 쓰지 않는다.

**사유** — 무작위 조합은 순수 단기기억 부하가 된다. 실제 관계로 묶으면 완성 음식 이미지가 **회상 단서**로 작동해, 재료를 못 외웠어도 음식만 기억하면 평생의 요리 경험에서 떠올릴 수 있다. 인지재활 측면에서도 의미기억과 연결하는 회상이 고령 사용자에게 적합하고 성취감도 크다.

### 6-13-2. 완성 형태 중복 배제 원칙 (신설)

> **완성 음식의 실루엣이 서로 겹치지 않도록 구성한다.**

10장의 결과 카드가 나란히 놓였을 때 어떤 음식인지 한눈에 구분되어야 한다. 실루엣이 비슷하면 3m 밖에서 보는 화면에서 서로 뒤섞여 보인다.

| 실루엣 카테고리 | 배정 음식 |
|---|---|
| 그릇 · 국물 | 미역국 |
| 그릇 · 죽 | 호박죽 |
| 유리컵 · 음료 | 수정과 |
| 넓적 원형 부침 | 김치전 |
| 접시 · 면 | 잡채 |
| 접시 · 네모 조림 | 두부조림 |
| 큰 덩어리 찜 | 갈비찜 |
| 꼬치 | 산적 |
| 작은 떡 여러 개 | 송편 |
| 원통 단면 나열 | 김밥 |

10개 카테고리에 10개 음식이 1:1로 배정되어 중복이 없다.

### 6-13-3. 음식 10종 · 레시피 (확정)

| 3 | **김밥** | 원통 단면이 나란히 놓인 형태 | 김 · 밥 | 2 |
| 4 | **호박죽** | 진노랑 걸쭉한 죽 · 그릇 | 호박 · 팥 | 2 |
| 5 | **미역국** | 짙은 초록 맑은 국물 · 그릇 | 미역 · 소고기 | 2 |
| 6 | **김치전** | 넓적한 붉은 원형 부침 | 김치 · 밀가루 · 달걀 | 3 |

### 6-13-4. 라운드 순서와 난이도 배분 (확정)

> **라운드 순서는 고정이다.** 무작위로 섞지 않는다.

| 재료 수 | 라운드 | 음식 |
|---|---|---|
| 1개 | R1 · R2 | 두부조림 · 수정과 |
| 2개 | R3 · R4 · R5 | 김밥 · 호박죽 · 미역국 |
| 3개 | R6 ~ R10 | 김치전 · 잡채 · 산적 · 송편 · 갈비찜 |

**사유** — 뒤로 갈수록 기억 부담이 늘어나는 점증 구조를 유지한다. 순서를 무작위로 하면 난이도 곡선이 사라지고, 반복 참여하는 사용자에게 예측 가능성이 주는 안정감도 잃는다. R10을 갈비찜으로 둔 것은 잔치 스토리의 마무리에 가장 어울리기 때문이다.

### 6-13-6. 오답 후보 산출 규칙 (확정)

| 항목 | 규칙 |
|---|---|

| 제약 1 | 같은 라운드 안에서 재료가 **중복 등장하지 않는다** |
| 제약 2 | **파와 시금치를 같은 라운드에 함께 배치하지 않는다** (6-13-7 참조) |

R1 두부조림은 정답 1개 + 오답 5개로 6칸이 모두 차므로 22종 풀은 충분하다.

### 6-13-7. 이미지 요건 (확정)

> **완성 음식 10종과 재료 22종은 서로 확실히 구분되어야 한다.**

#### 왜 필요한가

요리하기의 인지 과제는 **재료를 기억해 내는 것**이다. 그림이 서로 비슷하면 사용자가 재료를 정확히 기억하고도 화면에서 집어내지 못한다. 그 순간 오답은 **「기억 실패」가 아니라 「그림 구분 실패」**가 되어, 결과 데이터가 측정하려는 능력과 어긋난다.

#### 사용 환경 (참고 정보)

| 항목 | 값 |
|---|---|
| 표시 기기 | 대형 TV |
| 시청 거리 | 약 3m |
| 재료 이미지 표시 위치 | 후보 재료 6칸 (3×2) · SCR-018 |
| 완성 음식 이미지 표시 위치 | SCR-018-1 팝업 · SCR-019 결과 카드 10장 · SCR-020 |

#### 참고 사항

현재 재료 구성에서 **밥(김밥) ↔ 쌀가루(송편)**, **파(산적) ↔ 시금치(잡채)** 두 쌍이 서로 비슷해질 여지가 있다. 표현 방법은 디자인 파트에서 판단한다. 구분이 어렵다고 판단되면 기획에 알려 주면 **재료 구성 자체를 바꾸는 것도 가능**하다.

파와 시금치는 오답 후보 산출에서 **같은 라운드에 함께 배치하지 않는 것**으로 처리했다 (6-13-6).

> **표현 방법 · 화풍 · 검수 방식은 디자인 파트의 판단에 따른다.** 본 항목은 요건과 사용 환경만 전달한다.

| 재료 이미지 | **22종** |

# 7. 튜토리얼 구조

## 7-1. 화면 구성 원칙

각 게임은 튜토리얼 화면 1종을 가진다.

- 수확하기 튜토리얼: SCR-007
- 장보기 튜토리얼: SCR-012
- 요리하기 튜토리얼: SCR-017

동일 게임의 튜토리얼 화면을 개별 모드와 스토리 모드가 공용으로 사용한다.  
모드에 따라 하단 버튼만 달라진다.

### 화면 구성 (확정)

- 튜토리얼은 **짧은 동영상 + 단계별 설명**으로 구성한다.
- **실습(연습 조작) 단계는 두지 않는다.** 영상을 본 뒤 곧바로 게임에 진입한다.
- 단계별 설명은 영상 진행에 맞춰 현재 단계를 강조한다.
- 영상 구간이므로 자막과 음성 안내를 함께 제공할 수 있다.

### 단계 수 (확정)

| 게임 | 단계 수 | 화면 |
|---|---|---|
| ① 수확하기 | **3단계** | SCR-007 · 007-S |
| ② 장보기 | **4단계** | SCR-012 · 012-S |
| ③ 요리하기 | **4단계** | SCR-017 · 017-S |

와이어프레임에 단계 문구까지 반영되어 있다. **단계 문구 자체는 영상 대본에 맞춰 조정할 수 있는 예시**이며,
단계 수는 화면 구조에 해당하므로 확정으로 둔다.

## 7-2. 모드별 버튼 (v2.7 개정)

튜토리얼 화면은 게임 3종 공용 1종이며, **하단 버튼 구성만 모드별로 분기**한다.

| 모드 | 하단 버튼 |
|---|---|
| 개별 모드 | 이전으로(SCR-005 로비) · **시작하기** · 사용자 변경(SCR-003) |
| 스토리 모드 | **나가기**(SCR-004 모드 선택) · **시작하기** |

### 튜토리얼에는 건너뛰기를 두지 않는다 (확정 · v2.7)

화면목록 v6.1은 스토리 모드 버튼을 「시작하기 · 스킵」으로 규정했으나, 이를 **「나가기」로 교체**한다.

- 튜토리얼은 수행 방법을 익히는 단계이므로 건너뛰기를 두지 않는다.
- 스토리 모드에서 「이전으로」를 두면 개별 모드 로비로 빠져 흐름이 끊긴다.
- 「사용자 변경」을 두면 스토리 진행 중 사용자가 바뀌어 누적 기록이 섞인다.

### 파일 관리

개별 모드판과 스토리 모드판은 **별도 파일 2벌로 관리**한다. 두 화면은 상단 구조가 동일하고
하단 버튼만 다르므로, 수정할 때 반드시 짝으로 함께 갱신한다.

## 7-3. 잔여 항목

### 기획 결정 — **0건**

튜토리얼 구조(7-1) · 버튼 구성(7-2) · 건너뛰기 미제공(9-7)이 확정되어 기획 결정 항목은 없다.
스킵 버튼은 **튜토리얼에 두지 않는 것으로 확정**되었으므로 위치·명칭 항목은 소멸했다.

### 결정 예정 — **0건**

단계 수는 7-1에서 확정했다 (① 3 · ② 4 · ③ 4). 와이어프레임에 이미 반영되어 있다.

# 8. 결과 화면 체계

## 8-1. 개별 결과와 간이 결과 구분

| 구분 | 개별 모드 결과 | 스토리 모드 간이 결과 |
|---|---|---|
| 화면 | SCR-009 / SCR-014 / SCR-019 | SCR-010 / SCR-015 / SCR-020 |
| 목적 | 개인 수행 확인 | 서사적 보상과 다음 단계 연결 |
| 데이터 카드 | 사용 가능 | 사용하지 않음 |
| 수집·완성물 | 표시 | 표시 |
| 버튼 | 제공 | 제공하지 않음 |
| 진행 | 사용자 선택 | 일정 시간 후 자동 진행 |
| TTS | 허용 | 허용 |

### 제작 원칙 (확정)

- 개별 결과와 간이 결과는 **각각 독립된 개별 페이지로 제작한다.** 공유 컴포넌트 방식은 사용하지 않는다.
- 결과 화면의 **전체 활동 시간은 일시정지 시간을 제외**하고 계산한다.

## 8-2. 수확하기 결과 화면

SCR-009와 SCR-010은 현재 유효한 와이어프레임이 존재한다.

### 개별 결과 SCR-009

현재 문법:

- 정확하게 선택
- 다른 선택
- 전체 활동 시간 (일시정지 제외 — 확정)
- 라운드별 실제 수확물 나열
- 다시 하기
- 콘텐츠 선택
- 내 기록

### 수확물 구분 표현

- 정확한 선택: 선반 위에 온전하게 배치
- 다른 선택: 낮은 흙 단에 기울여 배치
- 벌레 먹은 작물: 큰 벌레 아이콘 병기
- 텍스트, O/X, 색상만으로 구분하지 않음

### 간이 결과 SCR-010

- 큰 완료 타이틀
- 수확물 나열
- 응원 멘트와 다음 활동 예고
- TTS
- 자동 진행 게이지
- 버튼 없음

### 간이 결과의 수집물 표시 규칙 (확정 · v2.4 추가)

간이 결과에서도 **정확한 선택과 다른 선택을 구분해 표시한다.** SCR-010 · SCR-015 · SCR-020에 공통 적용한다.

- 구분은 **위·아래 위치와 기울임**으로만 한다. 텍스트·O/X·색상 단독 구분은 사용하지 않는다.
- 위쪽: 제대로 담긴 것 / 아래쪽 바닥 단: 따로 담긴 것(기울여 배치)
- 수집물이 많은 게임은 **종류 단위로 묶고 개수 배지**를 붙인다. 낱개 나열하지 않는다.
- 이 방식은 수집물 총 개수와 무관하게 레이아웃이 변하지 않는다.
- 라운드 번호는 간이 결과에 표시하지 않는다. (개별 결과 전용)

## 8-3. 장보기·요리하기 결과 화면

| 화면 | 상태 |
|---|---|
| SCR-014 장보기 개별 결과 | **확정** — 5-13의 3카드 구성 |
| SCR-019 요리하기 개별 결과 | **확정** — 6-9의 3카드 + 음식 10장 나열 |

스토리 모드 간이 결과는 다음 방향을 유지한다.

| 화면 | 내용 |
|---|---|
| SCR-015 | 장바구니에 준비된 재료를 보여주고 다음 요리 단계 예고 |
| SCR-020 | 완성한 음식을 보여주고 엔딩·잔치상 단계 예고 |

## 8-4. 간이 결과 공통 원칙

- 점수·수치·등급을 표시하지 않는다.
- 버튼을 제공하지 않는다.
- 수집물이나 완성물이 순차적으로 등장한다.
- 응원 문구와 다음 활동 예고를 제공한다.
- 일정 시간 후 자동으로 다음 화면으로 넘어간다.
- 자동 진행 시간은 **6초**로 한다. **기준안**이며 프로토타입 검증 후 조정한다.
- **일시정지를 제공하지 않는다.** 본 절이 이미 「버튼을 제공하지 않는다」를 확정하고 있고, 6초 내외의 짧은 화면에 조작 요소를 넣으면 그 원칙이 무너진다.
- 자동 진행 중 남은 시간을 숫자로 표시하지 않는다. 진행 표현이 필요하면 게이지 등 비수치 형태로 한다.

## 8-5. 개인 누적 성과 이력 (SCR-023)

### 상태

**화면 구성과 세부 항목 모두 확정. 와이어프레임 산출 완료.**

> 표시 기간(최근 5회 고정) · 목록 건수(5건)가 아래 산출 규칙에서 확정되었으므로 **목록 넘김이 발생하지 않는다.**
> 도면 주석에 남아 있는 「표시 기간 범위 · 목록 표시 건수와 넘김 방식 결정 예정」은 **폐기 표기**이며 도면 수정 지시서에서 삭제한다.

| 영역 | 내용 |
|---|---|
| 누적 요약 | 함께한 날 · 전체 활동 시간(일시정지 제외) · 마지막 참여일 |
| 활동별 기록 | 게임 3종 각각 **최근 5회 성공 횟수 평균**을 `n / 10`으로 표시 |
| 회차별 막대 | 평균에 사용한 **그 5회의 회차별 기록**을 막대로 표시 |
| 최근 활동 목록 | 날짜 · 활동 · 결과 · 소요 시간 · **최근 5건** |
| 버튼 | 이전으로(호출 화면 복귀) · dwell 3초 |

### 산출 규칙

- 평균은 **반올림하여 정수로** 표시한다. 소수점을 표시하지 않는다.
- 기록이 5회 미만이면 **있는 만큼만 평균**을 내고, 막대도 그 수만큼만 표시한다. 빈 막대를 채워 넣지 않는다.
- 큰 숫자와 막대는 **동일한 5회 구간**을 가리켜야 한다.
- **표시 기간은 최근 5회로 고정한다.** 기간 필터(최근 1개월·3개월 등)를 두지 않는다.
- 최근 활동 목록도 **5건**으로 맞춘다. 화면 안의 숫자를 5로 통일해 「무엇을 기준으로 한 값인가」를 묻지 않게 한다.
- 기간별 추이는 관리자 화면(ADM-003-2)에서 본다. 사용자 화면은 최근 상태만 보여준다.

### 표시 금지

- 점수·등급·순위
- 다른 사용자와의 비교
- 기록이 줄어든 구간의 강조나 부정적 표현
- 상세 수치(평균 반응 시간·힌트 발동·좌우 편차 등) — **ADM 전용**

### 진입 경로 (확정)

> **기록 보기는 사용자 선택이 완료된 이후 화면에서만 제공한다.**

| 진입 화면 | 버튼 |
|---|---|
| SCR-005 콘텐츠 로비 | 내 기록 보기 |
| SCR-009 · 014 · 019 개별 결과 | 내 기록 보기 |
| SCR-022 최종 잔치상 | 내 기록 보기 — 스토리 모드의 유일한 기록 진입점 |

모두 dwell 3초로 선택한다. 「이전으로」는 호출한 화면으로 복귀한다.

### SCR-001에 두지 않는 이유 (확정)

- 기록은 **누구의 것인지 정해진 뒤에만** 의미가 있다. 사용자 선택 전에는 표시할 대상이 없다.
- SCR-001은 무인 대기 화면으로, 사용자 입력 요소를 두지 않는다.
- 요양원·복지관 통로에 방치된 상태에서 지나가던 사람이 잘못 누를 여지를 없앤다.

### 비회원(게스트) 처리

비회원으로 시작한 경우 수행 기록을 저장하지 않으므로 이 화면에 표시할 데이터가 없다.

> **비회원에게는 「내 기록 보기」 버튼 자체를 표시하지 않는다.** (확정)

버튼을 두고 빈 화면이나 안내문을 띄우면, 눌러도 아무것도 없는 버튼이 되어 혼란만 준다.
비활성 상태로 두는 것도 마찬가지다. 선택할 수 없는 요소는 화면에서 뺀다.

## 8-6. 결과 화면 문구 원칙 (확정)

> **평가어(잘·훌륭히)를 쓰지 않고 결과물 상태를 사실대로 서술한다.**
> **성공 횟수와 무관하게 항상 성립하는 문장을 사용하며, 해요체로 통일한다.**

### 배경

기존 「잘 거두셨습니다」에 어색하다는 피드백이 있었다. 세 가지 문제가 있었다.

| 문제 | 내용 |
|---|---|
| 문어체 | 「거두다」는 일상 대화에서 쓰지 않는 말이다 |
| **평가어** | 「잘」은 잘했다는 판정이다. 성공 횟수와 무관하게 모두에게 같은 문구가 나오는데 평가를 붙이면 공허하게 들린다. **점수·등급 비노출 원칙과도 충돌한다** |
| 문체 혼재 | 「~습니다」와 「~요」가 섞여 TTS 낭독 시 어색하다 |

### 확정 문구

| 화면 | 문구 |
|---|---|
| SCR-009 수확 개별 | 수확을 마쳤어요 / 담아 오신 것을 살펴보세요 |
| SCR-010 수확 간이 | **바구니가 가득 찼어요** / 필요한 재료가 모였어요 / 이제 시장에 다녀올까요? |
| SCR-014 장보기 개별 | 장보기를 마쳤어요 / 사 오신 재료를 살펴보세요 |
| SCR-015 장보기 간이 | **장바구니가 묵직해졌어요** / 필요한 것을 다 담았어요 / 이제 부엌으로 가 볼까요? |
| SCR-019 요리 개별 | 요리를 마쳤어요 / 만드신 음식을 살펴보세요 |
| SCR-020 요리 간이 | **음식이 다 되었어요** / 이제 상을 차려 볼까요? |
| SCR-022 최종 잔치상 | 잔치가 열렸어요 / 넉넉한 잔치상이 차려졌어요 |

자동 진행 안내도 해요체로 통일한다 — 「잠시 후 다음 이야기가 이어져요」 · 「잠시 후 처음 화면으로 돌아가요」

### SCR-022 문구 구조 (확정)

SCR-022는 **단계와 무관한 고정 문구**와 **단계별 멘트**를 나누어 쓴다.

| 위치 | 문구 | 성격 |
|---|---|---|
| 상단 고정 | `잔치가 열렸어요` | 3단계 공통 |
| 단계별 멘트 | 9-2의 3종 | 단계별 |

기존 표의 「넉넉한 잔치상이 차려졌어요」는 2단계 멘트와 겹치므로 상단 문구에서 뺀다.
상단에 단계를 암시하는 표현을 두면 단계별 멘트와 이중으로 평가하는 셈이 된다.

## 8-6-1. 전 화면 문구 통합표 (확정)

문구를 화면별로 흩어 두면 어투가 갈라진다. 사용자에게 보이는 모든 문장을 여기 모은다.
**아래 표에 없는 문구를 화면에 임의로 추가하지 않는다.**

### 게임 중 안내

| 화면 | 문구 |
|---|---|
| SCR-008 ① 수확하기 | `손을 대고 아래로 당겨 주세요` |
| SCR-013 ② 장보기 | `빛나는 발판으로 이동하세요` |
| SCR-018 ③ 요리하기 | `기억한 재료를 선택해 주세요` |
| SCR-018 목표 패널 | `「{음식명}」에 넣을 재료를 골라 주세요` |
| SCR-018-1 레시피 기억 | `다 외웠어요` (버튼) |

- 재촉·독촉 표현을 쓰지 않는다. `빨리` `서둘러` `아직` 계열 금지.
- 플레이 중 TTS를 쓰지 않는다.

### 라운드 판정

| 게임 | 성공 | 다른 선택 |
|---|---|---|
| ① 수확하기 | 문구 없음 (연출로만 표현) | 문구 없음 |
| ② 장보기 | 문구 없음 | 문구 없음 |
| ③ 요리하기 | `맛있는 요리가 완성되었어요` | `다른 재료가 들어갔어요` |

①·②는 라운드마다 문구를 띄우면 플레이 흐름이 끊긴다. ③은 슬롯 일괄 판정 구간이 있어 문구가 필요하다.

**「틀렸어요」 「실패」 「아쉬워요」를 쓰지 않는다.** 다른 선택은 사실만 서술한다.

### 개별 결과

| 화면 | 문구 |
|---|---|
| SCR-009 수확 | `수확을 마쳤어요` / `담아 오신 것을 살펴보세요` |
| SCR-014 장보기 | `장보기를 마쳤어요` / `사 오신 재료를 살펴보세요` |
| SCR-019 요리 | `요리를 마쳤어요` / `만드신 음식을 살펴보세요` |

세 화면 모두 **「~를 마쳤어요 / ~을 살펴보세요」** 구조를 지킨다. 성공 횟수와 무관하게 항상 성립한다.

### 간이 결과 (스토리)

| 화면 | 문구 |
|---|---|
| SCR-010 수확 | `바구니가 가득 찼어요` / `필요한 재료가 모였어요` / `이제 시장에 다녀올까요?` |
| SCR-015 장보기 | `장바구니가 묵직해졌어요` / `필요한 것을 다 담았어요` / `이제 부엌으로 가 볼까요?` |
| SCR-020 요리 | `음식이 다 되었어요` / `이제 상을 차려 볼까요?` |

**결과 상태 → 확인 → 다음 단계 권유** 3단 구조다. 마지막 줄의 `~볼까요?`가 다음 화면으로 이어지는 신호가 된다.

### 최종 잔치상

| 위치 | 문구 |
|---|---|
| 상단 고정 | `잔치가 열렸어요` |
| 1단계 | `정성이 담긴 상이 차려졌어요` |
| 2단계 | `이웃과 나눌 만한 상이 되었어요` |
| 3단계 | `온 동네가 모일 잔치상이 되었어요` |

### 자동 진행 안내

| 상황 | 문구 |
|---|---|
| 간이 결과 → 다음 | `잠시 후 다음 이야기가 이어져요` |
| SCR-022 → SCR-004 | `잠시 후 처음 화면으로 돌아가요` |

남은 시간을 숫자로 표시하지 않는다(8-4).

### 팝업

| 화면 | 문구 |
|---|---|
| POP-001 일시정지 | `잠시 쉬어 갈까요?` / 버튼 `계속하기` · `그만두기` |
| POP-002 그만두기 확인 | `지금 하시던 활동은 기록되지 않아요` / 버튼 `계속하기` · `그만두기` |

- 그만두기를 실패나 포기로 표현하지 않는다.
- `정말로` `아쉽게도` 같은 만류·아쉬움 표현을 쓰지 않는다.

### 공통 금지

| 금지 |
|---|
| 평가어 — `잘` `훌륭히` `아쉽게` `아깝네요` |
| 판정어 — `틀렸어요` `실패` `오답` |
| 재촉 — `빨리` `서둘러` `아직` |
| 비교 — 다른 사용자·이전 기록과의 대조 |
| 수치 — 점수·등급·순위·퍼센트 |
| 문체 혼재 — `~습니다`체 사용 |

## 8-7. 팝업 화면 체계 (확정)

## 코드 체계

팝업 화면은 **POP** 접두어로 별도 번호를 부여한다. 화면 흐름상의 독립 화면(SCR)과 구분하기 위함이다.

| 코드 | 명칭 | 성격 |
|---|---|---|
| **POP-001** | 일시정지 | 플레이 3종 공용. 일시정지 버튼 선택 시 호출 |
| **POP-002** | 그만두기 확인 | POP-001에서 그만두기 선택 시 호출 |
| ~~POP-003~~ | ~~설정~~ | **v2.9 폐기** — 소리 크기 · 음성 안내 · 프로그램 종료를 ADM-008 설정으로 이관 |

- 팝업은 호출한 화면 위에 오버레이로 표시하며, 뒤 화면은 유지된다.
- 팝업 표시 중에는 게임 진행과 경과 시간이 멈춘다.
- 팝업 자체에는 화면 번호 흐름(다음 화면)이 없다. 닫으면 호출 화면으로 복귀한다.

## 하위 단계 화면과의 구분

| 형식 | 용도 | 예 |
|---|---|---|
| `SCR-000` | 독립 화면 | SCR-013 장보기 플레이 |
| `SCR-000-1` | 같은 화면의 하위 단계 | SCR-018-1 레시피 기억 |
| `POP-000` | 팝업 오버레이 | POP-001 일시정지 |

## POP-001 일시정지 (구성 확정)

| 영역 | 내용 |
|---|---|
| 차폐 | 뒤 화면을 어둡게 덮되, 진행 중이던 화면임을 알 수 있게 한다 |
| 타이틀 | 잠시 멈추었습니다 |
| 버튼 | **계속하기**(주 CTA) · **그만두기** |
| 조작 | UI 버튼 dwell 3초 |
| TTS | 허용 (플레이 정지 상태로 해석) |
| 배치 | 상호작용 안전 영역 준수 |

## POP-002 그만두기 확인 (구성 확정)

| 영역 | 내용 |
|---|---|
| 타이틀 | 그만두시겠어요? |
| 안내 | 지금 하시던 활동은 기록되지 않아요 |
| 버튼 | **계속하기**(주 CTA) · 그만두기 |
| 이동 | 그만두기 선택 시 개별 모드는 SCR-005, 스토리 모드는 SCR-004로 이동 |
| 기록 | **진행 중이던 활동은 기록하지 않는다.** 결과 화면을 거치지 않고 바로 이동한다 |

- 그만두기를 실패나 포기로 표현하지 않는다.
- 진행 중이던 활동은 기록하지 않는다.

## 구 POP-003 설정 (v2.9 폐기 · ADM-008로 이관)

> **폐기 사유** — 관리자 화면이 별도 모니터에 상시 떠 있게 되어, 사용자 화면(TV)에 설정 팝업을 둘 이유가 사라졌다.
> 소리 크기 · 음성 안내 · 프로그램 종료 3종은 모두 **ADM-008 설정**으로 옮긴다. 「진입 경로」 항목도 함께 소멸했다.


| 항목 | 형태 |
|---|---|
| 소리 크기 | 작게 · 보통 · 크게 (3단계 버튼) |
| 음성 안내 | 켜짐 · 꺼짐 |
| 프로그램 종료 | 버튼 |
| 닫기 | 주 CTA |

### 원칙

- 설정 항목은 위 3종으로 확정한다. 추가 항목을 두지 않는다.
- **난이도 항목을 두지 않는다.** (1-9)
- 모든 설정은 **dwell로 누를 수 있는 단계 버튼** 형태로 한다. 슬라이더를 사용하지 않는다.
- 게임 규칙에 해당하는 값(판정 기준값·자동 복귀 시간 등)은 본 팝업에 두지 않고 ADM에서 다룬다.

### 참고

프로그램 종료를 본 팝업에 유지한다. 진입 경로가 결정되면 오조작 위험을 함께 검토한다.

# 9. 최종 잔치상 및 스토리 영상

## 9-1. 최종 잔치상 판정 (확정)

### 판정 기준

**세 게임의 라운드 성공 횟수 평균**으로 잔치상 단계를 결정한다.

```text
평균 = (수확하기 성공 + 장보기 성공 + 요리하기 성공) ÷ 30
→ 3단계 중 1개 적용
```

### 게임별 라운드 성공의 정의 (확정)

세 게임 모두 **10라운드 고정**이며, 성공 횟수의 최대값은 각각 10이다.

| 게임 | 라운드 단위 | 성공 조건 |
|---|---|---|
| ① 수확하기 | 수확물 1개 | 정확한 수확물을 선택 |
| ② 장보기 | 심부름 1건 (재료 1~3개) | **그 라운드의 재료를 전부 제대로 구매** |
| ③ 요리하기 | 음식 1개 (재료 1~3개) | **그 라운드의 재료가 전부 일치** |

②와 ③은 구조가 같다. 라운드 안의 재료를 하나라도 다르게 하면 그 라운드는 성공으로 세지 않는다.

- 게임별 가중치를 두지 않는다. 세 게임을 동등하게 본다.
- 반응 속도와 힌트 사용은 단계 판정에 사용하지 않는다.

### 단계 임계값 (기준값)

| 단계 | 평균 | 비고 |
|---|---|---|
| 1단계 | 하한 없음 | 최저 단계에도 하한을 두지 않는다 |
| 2단계 | 약 65% 이상 | |
| 3단계 | 약 85% 이상 | |

- 위 값은 **기준값이며 확정값이 아니다.** 현장 테스트 후 조정한다.
- **ADM에서 조정 가능한 값으로 설계한다.**
- 주의 — 사업계획서 KPI의 "성공률 90%"는 **시스템 인식 성능** 지표이며, 본 항목의 사용자 정답률과 무관하다. 두 값을 혼동하지 않는다.

## 9-2. 단계별 표현 (확정)

### 핵심 원칙

**단계 차이는 「양」이 아니라 「화려함」으로 표현한다.**

| 단계 | 차이 요소 |
|---|---|
| 1단계 | 기본 상차림 |
| 2단계 | 고명·장식 추가, 색감이 화사해짐 |
| 3단계 | 특별 음식 추가, 상 전체가 화려해짐 |

### 모든 단계 공통

- **상은 항상 가득 차 있다.** 빈 접시나 빈자리를 만들지 않는다.
- 모든 단계에서 음식은 정상적이고 먹음직스럽게 표현한다.
- 낮은 단계가 초라하거나 실패한 느낌을 주지 않는다.
- 점수·등급·퍼센트·성공률을 사용자에게 표시하지 않는다.

### 단계 명칭 — 내부 식별용 (확정)

> **단계 명칭을 사용자 화면에 표시하지 않는다.**

어떤 이름을 붙이든 3개를 나란히 두면 **등급으로 읽힌다.** 화면에는 상차림 그림과 멘트만 표시하고, 명칭은 기획·개발·관리자 화면에서 단계를 지칭하는 용도로만 쓴다.

| 단계 | 명칭 (기준안) |
|---|---|
| 1단계 | 우리 집 잔치상 |
| 2단계 | 이웃과 나누는 잔치상 |
| 3단계 | 온 동네 잔치상 |

서열이 아니라 **「누구와 나누는가」**로 읽히도록 잡았다. 사람이 늘면 상이 커지므로, 단계가 올라갈수록 상이 화려해지는 이유가 자연스럽게 설명된다.

**표시되지 않는 값이므로 명칭은 기준안이며 자유롭게 교체할 수 있다.** 교체해도 판정식·상차림 표현·멘트에 영향이 없다.

### 멘트

단계별로 다른 멘트를 사용하며 **모두 긍정형**으로 작성한다. 낮은 단계에도 부족하다는 뉘앙스를 넣지 않는다. 해요체로 통일한다(8-6).

| 단계 | 멘트 (기준안) |
|---|---|
| 1단계 | 정성이 담긴 상이 차려졌어요 |
| 2단계 | 이웃과 나눌 만한 상이 되었어요 |
| 3단계 | 온 동네가 모일 잔치상이 되었어요 |

멘트 최종 원고는 결과 화면 멘트 전반(12-2 B6)과 함께 어투를 맞춘다.

## 9-3. 화면 구성 (확정)

| 영역 | 내용 |
|---|---|
| 타이틀 | 잔치가 열렸습니다 |
| 중앙 | 최종 잔치상 이미지 (3단계 중 1개) |
| 결과 멘트 | 해당 단계의 멘트 |
| 하단 | **게임 3종의 성공 횟수**를 `n / 10` 형식으로 표시. 퍼센트·평균·등급은 표시하지 않는다 |
| 자동 복귀 | 시간이 지나면 **자동으로 SCR-004 모드 선택으로 복귀**한다. 진행 게이지로 남은 시간을 보여준다 |
| 버튼 | **2종 (v2.8 개정)** — ① 처음 화면으로 → SCR-004 모드 선택 (dwell 3초, 주 CTA) ② 내 기록 보기 → SCR-023 (dwell 3초) |
| 버튼 배치 | 화면 하단 중앙에 나란히 배치한다. 처음 화면으로가 좌측·주 버튼, 내 기록 보기가 우측·부 버튼이다. 두 버튼 모두 안전 영역(x420~1500) 안에 둔다 |
| 타이머 연동 | **내 기록 보기를 선택하면 자동 복귀 게이지를 정지**한다. 기록을 읽는 도중 화면이 넘어가지 않게 한다 |
| 복귀 후 | SCR-023에서 돌아와도 **자동 복귀 타이머를 재개하지 않는다** (확정). 「이전으로」를 선택해 SCR-022로 돌아온 뒤에는 사용자가 직접 다음 동작을 선택한다 |

## 9-4. 스토리 모드 종료 동선 (확정)

```text
SCR-022 최종 잔치상
  ├ 처음 화면으로 버튼 선택 → SCR-004 모드 선택
  ├ 내 기록 보기 선택 → SCR-023 개인 누적 성과 이력  (자동 복귀 게이지 정지)
  │     └ 이전으로 → SCR-022 복귀
  └ 자동 복귀 시간 경과 → SCR-004 모드 선택
```

### 내 기록 보기 신설 사유 (v2.8)

진입 경로가 SCR-005 · 009 · 014 · 019 네 곳뿐이었고 모두 개별 모드 화면이다.
스토리 모드로만 참여한 사용자는 자기 기록을 볼 방법이 전혀 없었다.
SCR-022는 스토리 모드에서 사용자가 마지막으로 머무는 화면이므로 여기에 진입점을 둔다.

### 자동 복귀 시간

| 항목 | 값 |
|---|---|
| 기준값 | **15초** |
| 성격 | ADM에서 조정 가능한 값으로 설계한다 |
| 근거 | 잔치상 이미지·멘트·성공 횟수 3칸을 읽는 데 필요한 시간을 고려. 현장 테스트 후 조정한다 |

## 9-5. 최종 잔치상 잔여 항목

기획 결정 항목은 없다.

| 항목 | 관리 |
|---|---|
| 단계별 멘트 | **확정** — 8-6-1 전 화면 문구 통합표 · 명칭은 화면에 표시하지 않는다 |

단계 임계값(9-1)은 **기준값으로 확정**되었으며 ADM에서 조정 가능한 값으로 설계한다.
자동 복귀 시간 15초도 **기준안**이며 현장 테스트 후 조정한다.

## 9-6. 스토리 영상의 역할

스토리 영상은 조작법을 자세히 가르치는 영상이 아니다.

목적:

- 사용자가 왜 각 게임을 수행하는지 이해하게 한다.
- 세 게임을 하나의 잔치 준비 과정으로 연결한다.
- 미니게임 사이의 맥락 전환을 돕는다.

## 9-7. 영상 UX 원칙

- 빠른 화면 전환을 피한다.
- 과도한 카메라 이동과 흔들림을 피한다.
- 자막과 TTS를 함께 제공한다.
- 자막은 짧고 크게 표시한다.
- 영상 종료 후 게임 준비 시간을 제공한다.
- 반복 이용 시 영상 피로를 줄이는 방법을 검토한다.

### 건너뛰기 (확정 · v2.8)

> **영상 4종 전부에 건너뛰기를 제공한다.**

| 항목 | 내용 |
|---|---|

## 10-1. 스토리 모드 진행 코드 (확정 · v2.7 신설)

게임 화면(튜토리얼·플레이)은 화면 구성이 공용이나, **스토리 모드로 진행할 때는 하위 코드 `-S`를 부여**해
흐름을 구분한다.

| 게임 | 개별 모드 | 스토리 모드 |
|---|---|---|
| 수확하기 튜토리얼 | SCR-007 | **SCR-007-S** |
| 수확하기 플레이 | SCR-008 → 009 | **SCR-008-S** → 010 |
| 장보기 튜토리얼 | SCR-012 | **SCR-012-S** |
| 장보기 플레이 | SCR-013 → 014 | **SCR-013-S** → 015 |
| 요리하기 튜토리얼 | SCR-017 | **SCR-017-S** |
| 요리하기 재료 선택 | SCR-018 → 019 | **SCR-018-S** → 020 |

**사유** — 같은 코드를 두 흐름이 공유하면 개별 결과와 간이 결과의 연결이 어긋난다.
프로토타입 검증에서 스토리 모드로 진행했는데 개별 결과가 표시되는 문제가 실제로 발생했다.
화면(그림)은 하나를 공유하고 흐름상의 코드만 분리한다.

하위 코드 형식은 6-9-1의 `SCR-000-1` 체계와 동일한 원칙이다.

# 16. 인터랙티브 HTML 프로토타입 방식 (확정)

판정값이 기준안 상태인 화면은 와이어프레임과 별도로 **브라우저에서 바로 실행되는 HTML 프로토타입**을 만들어 검증한다.

## 16-1. 표준 구성

| 영역 | 내용 |
|---|---|
| 형식 | **단일 HTML 파일** — 서버·설치 불필요, 더블클릭 실행 |
| 반응형 | SVG viewBox 스케일링, 마우스·터치 동시 지원 |
| 상단 | 판정값 조정 컨트롤 (임계값·선택지 수 등을 실행 중 변경) |
| 하단 | 실시간 데이터 로그 (라운드·정확/다른 선택·반응 시간·힌트 발동) |
| 토글 | 설계 주석 레이어 on/off |

## 16-2. 산출 이력

| 대상 | 상태 |
|---|---|
| SCR-008 수확하기 | 제작 완료 — **기준 템플릿**. 선택지 수(3~5), 당김 거리(80/120/180px) 조정 가능 |
| SCR-013 장보기 | **제작 완료** — 판정 영역(±80/110/140px) · 정지 인정 시간 · 정지 속도 임계 · 목표 수 조정 가능 |
| SCR-018 요리하기 | **제작 완료** — dwell 유지 시간 · 레시피 공개 시간 · 정답 재료 수 조정 가능 |
| 전 화면 통합본 | **제작 완료** — SCR-001~023 + POP 전 화면 이동 + 3게임 플레이 엔진 + 판정값 즉시 반영 (v34) |

## 16-3. 활용 목적

- 문서상 "프로토타입 테스트 후 확정"으로 남긴 수치를 실제 조작으로 결정한다.
- 개발 착수 전에 판정 방식의 체감을 확인한다.
- 실제 비전 카메라 추적과는 차이가 있으므로, 절대값이 아니라 **상대 비교와 방향 결정**에 사용한다.

# 17. 화면설계서 (확정)

와이어프레임과 별개로, 화면별 **UI 요소 명세와 기획 의도**를 정리한 문서를 유지한다.
와이어프레임이 「무엇이 어디에 있는가」라면, 화면설계서는 「그것이 무엇을 하고 왜 그렇게 두었는가」를 기록한다.

## 17-1. 문서 규격

| 문서 | 판본 | 페이지 |
|---|---|---|
| **사용자 화면설계서** | v2.2 | 39 (표지 1 + 이동 구조 2 + 화면 33 + 참고시트 3) |
| **관리자 화면설계서** | v1.5 | 18 (표지 1 + 이동 구조 2 + 화면 15) |

| 항목 | 내용 |
|---|---|
| 규격 | 16:9 (13.33 × 7.5 in) |
| 페이지 구성 | 좌측 와이어프레임 + 기획 메모(NOTES) / 우측 UI 요소 명세표 + 외부 이미지 자리 |
| 명세표 열 | NO · 요소명 · 기능 설명 · 비고 |
| NO 규칙 | 와이어프레임의 붉은 번호 배지와 **1:1로 일치**시킨다. 배지가 없는 보조 항목은 `–`로 표기한다 |
| 이동 구조 | 두 설계서 모두 앞부분에 **박스형 플로우 + 화면별 이동 명세표**를 둔다 (코드 · 이동처 · 넘김 방식) |


## 17-2. 배열 원칙 (확정)

> **화면 번호 순서가 아니라 모드별로 배열한다.**

| 구간 | 페이지 | 내용 |
|---|---|---|
| 표지 | 1 | |
| 화면 이동 구조 | 2 ~ 3 | 박스형 플로우 — 코드 · 이동처 · 넘김 방식 |
| 공통 진입 | 4 ~ 7 | SCR-001 ~ 004 |
| 스토리 모드 | 8 ~ 22 | SCR-006 ~ 022 (`-S` 계열 포함) |
| 개별 모드 | 23 ~ 36 | SCR-005 · 007 ~ 019 · REF-U 3장 포함 |
| 공통 화면 · 팝업 | 37 ~ 39 | SCR-023 · POP-001 · POP-002 |
| **참고시트** | **26 · 30 · 35** | **REF-U · REF-A는 설명 대상 화면 바로 다음 쪽에 둔다** — 따로 모아 두면 어느 화면 이야기인지 알기 어렵다 |

> **REF-U 3장 처리 (v4.7 완료)** — 이미지 전용 슬라이드라 텍스트가 없었다. 그림을 덮지 않도록
> **대체 텍스트(alt)와 발표자 노트**에 코드·제목·배치 근거를 넣어 검색과 식별이 되게 했다.
> 화면 안에는 이미 코드가 그려져 있으므로 별도 헤더를 얹지 않는다.

번호순으로 늘어놓으면 스토리와 개별 흐름이 뒤섞여 읽는 사람이 어느 모드의 화면인지 매번 되짚어야 한다.
각 페이지 우상단에 **모드 배지**(공통 회색 / 스토리 파랑 / 개별 초록 / 팝업 금색)를 표시해 구간을 식별한다.

## 17-3. 중복 화면 처리 (확정)

플레이 화면은 그림 한 벌을 두 흐름이 공유한다. 설계서에서는 페이지를 따로 두되 명세를 중복 기재하지 않는다.

| 화면 쌍 | 처리 | 기준 페이지 |
|---|---|---|
| SCR-008 / 008-S | 동일 명시 — 차이 2건(진입 · 종료)만 기재 | 008-S (p10) |
| SCR-013 / 013-S | 동일 명시 | 013-S (p14) |
| SCR-018 / 018-S | 동일 명시 | 018-S (p19) |
| SCR-018-1 | 두 모드 공용 · 개별 구간에도 흐름 확인용 페이지 유지 | 스토리판 (p18) |
| SCR-007 / 007-S 등 튜토리얼 3쌍 | **각각 전체 명세 유지** — 하단 버튼이 실제로 다르다 | 각자 |

수정이 발생하면 **기준 페이지를 먼저 고치고** 참조 페이지는 차이 항목만 갱신한다. 같은 내용을 두 곳에 두지 않는다.

## 17-4. 반영 순서 (확정)

규칙이 바뀌면 다음 순서로 반영한다. 역방향으로 확정하지 않는다.

```text
본 문서(통합인계자료)  →  화면목록  →  와이어프레임  →  화면설계서 · 플로우차트 · 프로토타입
```

## 17-5. 함께 관리하는 산출물

| 산출물 | 용도 |
|---|---|
| 통합 플로우차트 (박스형) | 전 화면 이동 구조를 코드 · 이동처 · 넘김 방식으로 한 장에 정리 |
| 화면 흐름도 (스토리 / 개별 분리 · 세로 · 와이드) | 와이어프레임 썸네일 기반 흐름 파악용 |

# 18. 관리자 화면 (확정)

## 18-1. 운영 방식 (확정)

```text
엣지 PC
  ├─ HDMI 1 → 대형 TV        → 게임 화면 (사용자)
  └─ HDMI 2 → 관리용 모니터   → 브라우저로 관리자 화면 (직원)
                                + 무선 키보드 · 마우스
```

| 항목 | 확정 내용 |
|---|---|
| 형태 | **웹 페이지** — 앱 설치 없음 |
| 서버 | 외부 서버 없음. 엣지 PC 내부 로컬 웹서버 |
| 접속 | `localhost` — 네트워크 불필요 |
| 표시 기기 | 엣지 PC의 두 번째 모니터 |
| 입력 | 무선 키보드 · 마우스 |
| 화면 규격 | 1920 × 1080 · 반응형 미적용 |
| TV 표시 | **게임만.** 관리자 화면을 TV에 띄우지 않는다 |

### TV에 두지 않는 이유

| 이유 | 내용 |
|---|---|
| 개인정보 | 사용자 실명과 참여 기록이 공용 공간에 공개된다 |
| 가독성 | 관리 화면은 정보 밀도가 높고 TV는 3m 밖에서 보는 화면이다 |
| 작업 자세 | 이름 입력 · 목록 클릭은 앉아서 하는 일이다 |

### 하드웨어 추가 요청

관리용 모니터 1대와 무선 키보드 · 마우스 1세트가 필요하다. 사업계획서의 H/W 구성(디스플레이 · 비전 카메라 · 엣지 PC · 전원)에 포함되어 있지 않다.

### 확장 여지

공유기를 추가하면 같은 웹 화면을 사무실 태블릿 · 노트북에서도 열 수 있다. 화면 설계는 그대로 재사용된다. **이번 범위에 포함하지 않는다.**

## 18-2. 인증 (확정)

| 항목 | 내용 |
|---|---|
| 방식 | 숫자 **4자리 번호** |
| 인증 시점 | **프로그램 실행 시 1회만** |
| 자동 잠금 | 두지 않는다 |
| 화면 간 이동 | 다시 묻지 않는다 |
| 마스터 번호 | **0000 상시 유효** — 번호를 바꿔도 유지 |
| 연속 실패 잠금 | 1차 범위에서 두지 않는다 |

### 마스터 번호를 유지하는 이유

서버가 없어 원격으로 번호를 재설정해 줄 수 없다. 번호를 잊으면 기기를 초기화하는 것 외에 방법이 없으므로 복구용 번호를 남긴다. **마스터 번호는 화면에 표시하지 않고 설치 안내서로만 전달한다.**

### 번호의 성격

이 번호는 **오조작 방지 장치이지 보안 장치가 아니다.** 사용자·방문객이 실수로 관리 화면을 건드리는 것을 막는 것이 목적이며, 기기가 시설 안에 물리적으로 놓여 있으므로 외부 침입 차단은 목적이 아니다.

### 끝내기 3종 (확정)

| 동작 | 결과 |
|---|---|
| **화면 잠그기** | 번호 입력 화면으로 복귀 · **사용자 화면은 그대로 돌아간다** |
| **관리 화면 닫기** | 브라우저 창만 닫는다 · 사용자 화면은 그대로 돌아간다 |
| **프로그램 종료** | 사용자 화면까지 모두 종료 · 확인 팝업을 거친다 |

「로그아웃」이라는 말을 쓰지 않는다. 계정 개념이 없고 번호 하나뿐이므로 **「잠그기」**로 표기한다.

## 18-3-1. 활동별 지표 4종 (확정 · v3.9 신설)

ADM-003-2(활동별 변화 추이)와 ADM-006-2(활동별 통계)는 **활동 탭 3개**를 두고, 탭마다 지표 4종을 보여준다.
자리(1~4번)는 세 게임이 공유하고 **이름과 산출 근거만 달라진다.**

| 자리 | ① 수확하기 | ② 장보기 | ③ 요리하기 | 산출 근거 |
|---|---|---|---|---|
| 1 | 정확하게 선택 | **제대로 산 재료** | 재료를 맞게 담음 | 4-8 · **5-14 #8** · 6-12 |
| 2 | 평균 반응 시간 | **평균 반응 시간** | 평균 반응 시간 | 4-8 · **5-14 #3** · 6-12 |
| 3 | 다른 선택 | **다르게 산 재료** | 재료가 달랐던 음식 | 4-8 · **5-14 #1** · 6-12 |
| 4 | 도움 받은 횟수 | 도움 받은 횟수 | 도움 받은 횟수 | 4-8 · **5-14 #5** · 6-12 |

### 2번 지표 명칭 통일 (확정)

**세 게임 모두 「평균 반응 시간」을 쓴다.** 장보기의 실제 측정값은 5-14 #3(목표 점등부터 도착까지 걸린 시간)이지만,
화면 지표명은 통일한다. 게임마다 이름이 다르면 담당자가 탭을 옮길 때마다 같은 자리의 값을 다시 해석해야 한다.

### 3번 지표 표기 (확정)

| 게임 | 표기 |
|---|---|
| ① 수확하기 | 다른 선택 |
| ② 장보기 | **다르게 산 재료** |
| ③ 요리하기 | 재료가 달랐던 음식 |

> **「잘못 도착」·「틀린」 등 평가 표현을 쓰지 않는다.** 관리자 화면도 사용자 대면 표기 원칙(5-11 · 8-6)을 따른다.
> 담당자가 그대로 읽어 사용자에게 전달하는 상황을 전제한다.

### 축반전 적용

1~4번 중 **2번 · 3번 · 4번은 「낮을수록 좋은」 지표**이므로 18-4의 축반전 규칙을 적용한다.

## 18-4. 표시 원칙 (확정)

### 운영자 전제

| 항목 | 내용 |
|---|---|
| 누구인가 | 요양원 · 복지관의 요양보호사, 사회복지사, 프로그램 담당자 |
| 모르는 것 | 판정 임계값, 좌표, 카메라 파라미터, 반응 시간의 의미 |
| 두려운 것 | 잘못 눌러서 프로그램이 망가지는 것 |

### 여섯 가지 원칙

1. **숫자를 해석 없이 던지지 않는다.** 「성공률 87%」가 아니라 「사람을 잘 못 알아봐요 → 발자국 위치를 확인해 주세요」.
2. **되돌릴 수 없는 조작은 2단계 확인.** 실행 버튼만 위험도에 따라 색이 바뀐다.
3. **개발 파라미터를 노출하지 않는다.** 판정값 · 시간값은 SVC 서비스 모드로 분리한다.
4. **고장 났을 때 다음 행동을 알려준다.** 오류 코드를 쓰지 않는다.
5. **호칭은 「사용자」로 통일한다.** 관리 화면에서 「어르신」을 쓰지 않는다 — 데이터 항목명으로 부적절하다.
6. **사용자 화면 원칙(dwell · 안전 영역 · 큰 글씨)을 적용하지 않는다.**

### 지표 계산 기준 (확정 · v4.2 신설)

관리자 화면의 지표 4종을 **어떤 단위로 모아 어떻게 계산하는지** 정한다. 자세한 내용은 **REF-A-07**을 본다.

> **모든 지표는 「한 번의 참여(10라운드)」를 단위로 모으고, 선택한 기간의 평균을 표시한다.**

| 지표 | 무엇을 세는가 | 계산 | 단위 |
|---|---|---|---|
| 정확하게 선택 | 10라운드 중 성공한 라운드 수 | 참여별 성공 라운드 수 ÷ 참여 횟수 | `n / 10` |
| 평균 반응 시간 | 목표 제시부터 선택 확정까지 | 라운드별 시간 합 ÷ 라운드 수 | 초 |
| 다른 선택 | 목표가 아닌 것을 고른 횟수 | 참여별 횟수 합 ÷ 참여 횟수 | 번 |
| 도움 받은 횟수 | 자동 힌트가 발동한 횟수 | 참여별 발동 횟수 합 ÷ 참여 횟수 | 번 |

**게임별 반응 시간 끝점** — 수확하기는 수확 확정, 장보기는 발판 도착, 요리하기는 첫 재료 선택 시점이다.

| 예외 | 처리 |
|---|---|
| 힌트를 받고 성공 | **성공에 포함**한다 (4-6 · 5-9 · 6-5) |
| 일시정지 시간 | 반응 시간에서 **제외**한다 |
| 기간 안에 참여가 없음 | **값을 0으로 쓰지 않고 「기록 없음」으로 비운다** |
| 표시 자리 | 소수 첫째 자리까지 반올림한다 |

> **최종 계산 방식은 개발 판단이다.** 본 절은 기획이 요구하는 의미를 정한 것이다.

### 변화 판정 규칙 (확정 · v4.1 신설)

ADM-003-2의 **변화 요약 4카드** 문구를 정하는 규칙이다.

```text
변화량 = 최근 구간 값 − 처음 구간 값
|변화량| < 0.5   → 「비슷한 수준」
구간 수 < 2      → 「비교 기록 부족」
```

| 지표 | 값이 커짐 | 값이 작아짐 |
|---|---|---|
| 정확하게 선택 | **늘었어요** | 줄었어요 |
| 평균 반응 시간 | 느려졌어요 | **빨라졌어요** |
| 다른 선택 · 도움 받은 횟수 | 늘었어요 | **줄었어요** |

- 비교 대상은 **그래프 양 끝의 처음 구간과 최근 구간**이다. 중간 구간은 계산에 쓰지 않는다.
- 주간 · 월간 · 일별을 바꾸면 **구간 단위만 달라지고 규칙은 같다.**
- 지표별로 다른 임계값을 두지 않는다. **0.5 하나로 네 지표를 판정한다.**
- 비율(%) 방식은 처음 구간이 0일 때 계산이 성립하지 않아 채택하지 않는다.

자세한 내용은 **REF-A-05**를 본다.

### 축반전 규칙 (확정)

개인 성과 그래프(ADM-003-2)에 적용한다.

> **「낮을수록 좋은」 지표(반응 시간 · 다른 선택 · 도움)는 막대가 커지는 방향으로 통일하고, 색은 항상 초록 고정한다. 실제 값은 막대 위 라벨로 별도 표기한다.**

- ↑↓ 화살표를 쓰지 않고 **「늘었어요 / 빨라졌어요 / 줄었어요 / 비슷한 수준」** 문구만 쓴다.
- 참여자 수 · 참여 횟수 같은 **운영 수치에는 적용하지 않는다**(방향성 문제가 없다).

### 활동별 지표명 전환

활동 탭에 따라 세 번째 지표명이 바뀐다.

| 활동 | 지표명 |
|---|---|
| 수확하기 | 다른 선택 |
| 장보기 | **다르게 산 재료** |
| 요리하기 | 재료가 달랐던 음식 |

# 부록 A. 벌레 쫓기 변주 설계안

상태: **보류**

수확하기의 기본 게임 완성 후 채택 여부를 다시 검토한다.  
벌레 먹은 작물의 정적 식별 표식과는 별개의 변주다.

## A-1. 목적

- 순수 재미와 추가 팔 움직임 제공
- 점수, 덤 재료, 최종 잔치상 보상에는 반영하지 않음
- 무시해도 기본 수확 진행에 영향을 주지 않음

## A-3. 검토 사양

- 벌레가 정지·호버할 때만 쫓기 판정 활성
- 넝쿨과 떨어진 완충 공간에서 호버
- 손 진입과 큰 움직임 1회로 관대하게 판정
- 무시하면 일정 시간 후 자동 퇴장
- 성공 시 코믹한 시각 연출과 효과음
- 플레이 중 TTS 사용 금지
- 등장 빈도는 낮게 설정
- 반응 시간은 내부 보조 데이터로만 기록

## A-4. 채택 전 검증

- 목표 탐색 혼란 여부
- 고령 사용자의 시각 피로
- 고음 효과음의 스트레스
- 손 커서·수확 판정 간섭
- 운영자 설정에서 on/off가 필요한지
