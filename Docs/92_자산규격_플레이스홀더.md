# 자산 규격 · 플레이스홀더 운용 (개발 기준)

> 작성: 2026-08-31 · 근거: 05 발주서(수량·요건 확정) · 07 문서 2-5(화면 좌표)
> 목적: 자산 수급 전 개발 진행 + **수령 시 아래 규칙대로 파일만 넣으면 코드 수정 없이 교체**되게 한다.

## 1. 교체 메커니즘

- 코드는 `ArtCatalog`(`Assets/Scripts/UI/ArtCatalog.cs`)를 통해서만 그림을 찾는다.
- 스프라이트가 **있으면 적용, 없으면 지금의 X-Box 플레이스홀더(색 박스 + 한글 라벨)**가 그대로 나온다.
- 파일 위치: `Assets/Resources/Art/<분류>/<이름>.png` — 이름은 **게임 데이터의 한글 명칭 그대로** (별도 매핑표 없음).

## 5. 플레이스홀더 상태 (자산 도착 전)

- 색 박스 + 한글 라벨(현행 유지) = X-Box 방식. 벌레 먹은 작물은 어두운 색 + `(벌레)` 표기, 결과 병기는 `🐛`.
- 아바타는 카드 배경색만으로 구분(색 8종 = 코드 `CardColors`), 그림 자리는 `그림 n` 라벨.
- 스프라이트가 일부만 도착해도 된다 — 있는 것만 교체되고 나머지는 플레이스홀더 유지.

## 6. 수령 시 체크리스트 (발주서 05 검수 기준 발췌)

1. 파일명·폴더가 2장 표와 일치하는가 (한글 명칭 그대로)
2. 3m 거리 구분: 음식 10종 나열 · 밥↔쌀가루 · 파↔시금치 · 벌레 먹은 작물
3. 금지 확인: X표·빗금·평가 표현 없음 · 발판 버튼 형태 아님 · 점포 지붕 없음
4. 에디터 실행 → 각 화면에서 교체 확인 · `[SafeArea]` 경고 없음
