### 1 · 2 · 3 보충 — 어떤 값을 바꾸고 어떤 값은 그대로 두는가

- **`success_count` 는 바꾸지 마세요.** 세 게임 모두 「라운드 성공 수(0~10)」가 맞고(5-14 #9), A3 · 내 기록 보기 n/10 · 최종 잔치상 판정이 이 값을 씁니다. 지금 서버 재계산과 게임 화면이 일치하는 것을 시뮬레이션 14건 전부에서 확인했습니다.
- 바뀌는 것은 **ADM-003-2 · ADM-006-2 활동별 지표 1번(장보기) · 3번(요리)의 계산**과 **도움 횟수(장보기)** 뿐입니다.
- 장보기 재료 총량은 **20** 입니다(5-6 목표 수 배분 합계). 명세 4-6 의 「ERD 는 최대 30」은 오기입니다.
- 3번 근거(시뮬레이션 실측 — 게임 화면 값 vs 서버 재계산 `hint_count`):

| 사용자 | 기록 | 게임 도움 횟수 | 서버 응답 | 차이 = 복귀 유도 힌트 |
|---|---|---|---|---|
| 김명희 | 장보기 개별 10/15 | 12 | 6 | 6 |
| 조복순 | 장보기 스토리 10/17 | 8 | 7 | 1 |
| 조복순 | 장보기 개별 10/15 | 7 | 3 | 4 |

게임이 보내는 장보기 라운드 모양(라운드 수준 `hint_count` 포함):

```json
{ "round_no": 3, "round_sec": 13.2, "hint_count": 1,
  "items": [ { "seq": 1, "target_item": "당근", "target_zone": "L1", "bought_item": "당근", "bought_zone": "L1",
               "is_matched": true, "arrive_sec": 3.3, "hint_count": 0 }, … ] }
```
