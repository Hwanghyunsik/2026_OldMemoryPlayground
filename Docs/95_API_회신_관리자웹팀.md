## 2. 기획 확정과 달라 수정을 요청하는 것

### R1. 장보기 1번 지표 「제대로 산 재료」는 **재료 단위**

| | 명세 구현 | 기획 확정 |
|---|---|---|
| ADM 활동별 지표 1번(장보기) | 재료가 모두 `is_matched` 인 **라운드 수** | **제대로 산 재료 수** — `is_matched: true` 인 **재료(items) 수** · 참여당 최대 **20** (18-3-1 표 1번 「제대로 산 재료」 · 5-14 #8) |

- 명세가 근거로 든 REF-A-07 「10라운드 중 성공한 라운드 수」는 세 게임 공통의 일반 정의이고, 18-3-1 이 **장보기만 재료 단위로 따로 정해 두었습니다**(지표 이름도 「정확하게 선택」이 아니라 「제대로 산 재료」). 같은 절에서 3번 지표도 「다르게 산 재료」(재료 단위)인데, 이쪽은 명세 구현이 이미 재료 단위라 1번만 맞추면 됩니다.
- **`success_count`(A2 · A3 · 내 기록 보기 n/10 · 최종 잔치상 판정)는 지금처럼 라운드 단위(0~10)를 유지**해 주세요 (5-14 #9 「라운드 성공 횟수 0~10」 — SCR-022 · SCR-023 · ADM 통계가 이 값을 씁니다). 바뀌는 것은 ADM-003-2 · ADM-006-2 의 **활동별 지표 1번 계산만**입니다.
- 재료 총량은 **20**입니다(5-6 목표 수 배분 합계 · 명세 4-6 의 「ERD 는 최대 30」은 오기).

### R2. 요리 3번 지표 「재료가 달랐던 음식」은 **라운드(음식) 단위**

| | 명세 구현 | 기획 확정 |
|---|---|---|
| ADM 활동별 지표 3번(요리) | 다르게 담은 **재료 수** | **재료가 달랐던 음식 수** — `is_matched: false` 인 pick 이 **하나라도 있는 라운드 수** (18-3-1 표 3번 · 6-12) |

→ 93-1 ERD §4 의 정의(「다른 재료가 섞인 라운드 수」)가 기획과 같습니다.

### R3. 장보기 도움 횟수에 **라운드 수준 `hint_count`** 포함

- 장보기 자동 힌트는 두 가지입니다: ① 재료별 「빛나는 발판으로 가세요」(→ `items[].hint_count`) ② 구매 뒤 **「가운데로 돌아오세요」 복귀 유도**(재료에 속하지 않음). 기획의 도움 횟수는 「자동 힌트가 발동한 횟수」(18-4) 라 ②도 포함합니다.
- 게임은 **`rounds[].hint_count`**(라운드 수준 · 복귀 유도 힌트 수)를 추가로 보냅니다. 서버가 **도움 횟수 = Σ items[].hint_count + Σ rounds[].hint_count** 로 세 주세요. 지금은 「모르는 키 제거」 규칙으로 버려지므로 당장 오류는 없지만, 그동안 장보기 도움 횟수가 게임 화면보다 적게 집계됩니다.
- 2026-10-19 개발 서버 실측(게임 시뮬레이션): 김명희 장보기 개별 — 게임 12 · 서버 응답 6 / 조복순 장보기 스토리 8 · 7, 개별 7 · 3. 차이가 전부 복귀 유도 힌트입니다. 수확·요리와 `success_count` 14건은 모두 일치했습니다.

```json
{ "round_no": 3, "round_sec": 13.2, "hint_count": 1,
  "items": [ { "seq": 1, "target_item": "당근", "target_zone": "L1", "bought_item": "당근", "bought_zone": "L1", "is_matched": true, "arrive_sec": 3.3, "hint_count": 0 }, … ] }
```

### R4. A3 「내 기록 보기」 — 활동별 최근 5회를 낼 수 있게

- 게임 SCR-023 확정 규격(8-5): **활동 3종 각각 최근 5회 성공 횟수 평균 + 그 5회의 막대** · 최근 활동 5건(스토리 한 판 3종은 **한 줄로 묶음**).
- `limit=5` 로는 활동별 5회를 모을 수 없습니다. 둘 중 하나를 부탁드립니다:
  1. `GET /api/participants/{id}/play-sessions?activity=harvest&limit=5` 처럼 **`?activity=` 필터** 추가 (게임이 3번 호출), 또는
  2. 응답에 `per_activity: { "harvest": [최근 5건 요약], "shopping": [...], "cooking": [...] }` 추가 (1번 호출)
- 반영 전까지 게임은 `limit=50` 으로 받아 활동별로 자릅니다.

### R5. 카드 배경색 8색 — 게임 디자인 시안 색으로 통일

### R6. `started_at` 이 서버보다 1시간 넘게 미래면 400 → 기록 유실 위험

- 게임은 400 을 재시도하지 않으므로(명세 3-3) 게임 PC 시계가 틀어진 날의 참여 기록이 **영구히 사라집니다**. 시설 PC 는 시계가 어긋나는 일이 드물지 않습니다.
- 요청: 거절 대신 **저장하고 `clock: warn` 처럼 표시**해 주세요(B1 `device_time` 으로 이미 시계 어긋남을 보고 있으니 같은 기준으로). 또는 400 응답에 서버 현재 시각(`server_time`)을 넣어 주시면 게임이 보정해 다시 보낼 수 있습니다.

## 3. 정의 안내 (서버 계산은 그대로 · 설명 문구 참고용)

| 항목 | 게임이 보내는 값의 정의 | 명세와 |
|---|---|---|
| 수확 `reaction_sec` | **시작 강조 연출이 끝난 시점(t=0)** 부터 당김 확정까지 (4-4) — 「목표 제시」 직후가 아니라 약 1초 강조가 끝난 뒤부터 | 설명만 다름 |
| 수확 `result` | `target` 목표 · `other` 다른 작물 · `bug` 벌레 먹은 작물. 다른 선택 지표 = `other` + `bug` | 일치 |
| 장보기 `arrive_sec` | 목표 점등부터 발판 도착 판정까지 · 평균 반응 시간으로 표기(18-3-1) | 일치 |
| 장보기 3번 「다르게 산 재료」 | `is_matched: false` 재료 수 | 일치 |
| 요리 `reaction_sec` | 차림표 팝업 닫힘부터 **첫 재료 선택**까지 (18-4) | 일치 |
| 요리 `review_count` | 차림표 다시 보기 — 도움 횟수와 별개 | 일치 |
| `duration_sec` | 일시정지 제외(게임이 timeScale=0 으로 정지해 계측) · `paused_sec` 별도 | 일치 |
| 기록하지 않는 것 | 비회원 참여 · 10라운드 전 중도 종료 | 일치 |
| 사용자 삭제 | 기록 함께 삭제(FN-20 확정) — 기본 동작 그대로 | 일치 |
